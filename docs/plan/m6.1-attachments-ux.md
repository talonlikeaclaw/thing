# M6.1 — Attachments UX, schema 6, v0.7.0

Target: workspace `0.7.0`, on-disk `schema: 6`. Seven checkpoints; one per turn under the AGENTS
delivery protocol.

## Context

M6 shipped one upload surface, one read surface, a `file`/`image` property holding **one** path,
record covers, gallery image covers and a lightbox. The committed M6.1 follow-up was **body images
only** (`docs/plan/m6-files-and-images.md` §1, §8). This milestone widens it to the ask: a record
holds many files and photos, the whole space has one browsable library with kind/type filters, and
images can be pasted into the body.

A new `attachments` property format is a format change: a schema-5 binary cannot parse the format
and would fail per file instead of refusing the space. `FORMAT_VERSION` exists for exactly that, so
this is **0.7.0**, matching every earlier schema bump (2→0.2.0 … 5→0.6.0). It is not a 0.6.1 patch.

## Locked decisions

1. **One new format, `attachments`**, value = ordered `Value::List` of file paths. Existing `file`
   and `image` stay single-valued. A record that needs a photo set carries one `Photos` property,
   not twenty properties.
2. **Order is upload order.** New uploads append; no reorder control. Removing items keeps the rest
   in place. Removing the last item clears the key (`null` on PATCH), never writes `[]`.
3. **One spelling of a path** stays `files/<sha256>/<name>`; every validation uses
   `store::is_file_path`.
4. **Attachments are not filterable by text.** Only `is_empty` / `is_not_empty` are legal for the
   format; sorting compares the files' basenames.
5. **The library lists unique paths, not references.** One card per stored path; each card names
   the live or trashed records that use it (deduped by record, cover before properties before
   body). A path referenced only by trash is not unused and is not collected.
6. **Body images count as references.** Any `files/<hash>/<name>` token in a body is protected from
   GC and reported when its bytes are missing (`field: "body"`), because GC must never delete bytes
   a body renders.
7. **`Set as cover` lives on the record's attachment tiles** (unambiguous target). The library is
   for browsing; a card whose image is used by several records does not guess.
8. **Clipboard paste is explicit.** The attachment field has a `Paste` action that calls
   `navigator.clipboard.read()`; the body editor also handles a real paste event. A denied
   clipboard shows a sentence and the picker still works.

### Checkpoint 1 — Schema 6: the `attachments` format

- `crates/core/src/lib.rs`: `FORMAT_VERSION = 6`, doc comment reads `schema: 6`; rename the test to
  `format_version_is_six_and_still_reads_one` and assert 6.
- `crates/core/src/model.rs`: `PropertyFormat::Attachments` after `Image` (serde snake_case already
  yields `"attachments"`); `pub const MAX_ATTACHMENTS: usize = 200;`. The `Value` doc comment gains
  "`Attachments` is `List`".
- `crates/core/src/value.rs`: `parse_value` arm `Attachments => string_list(raw).map(Value::List)`;
  `expected(Attachments) = "a list of file paths"`; `compare` gains
  `(List(x), List(y)) if format == Attachments` comparing basenames element-wise with
  `compare_text`, then length. Basename = the part after the last `/`.
- `crates/core/src/validate.rs`:
  - `variant_matches`: `Attachments => matches!(value, Value::List(_))`.
  - the format/value match gains: every entry must satisfy `crate::store::is_file_path`, the list
    holds at most `MAX_ATTACHMENTS`, no path appears twice. Messages:
    `"expected a list of file paths"`, `"holds at most 200 files"`, `"lists the same file twice"`.
  - `validate_condition` refuses any op other than `IsEmpty`/`IsNotEmpty` for an `Attachments`
    column with `invalid(key, "supports only is_empty and is_not_empty")`.
- `crates/core/src/index.rs`:
  - `AttachmentReference` becomes owned and gains `title: String`, `icon: Option<String>`,
    `type_key: String`, `rev: u64`, `updated_at: OffsetDateTime`, `trashed: bool`; `path: PathBuf`,
    `file: String`, `field: String`. `attachment_references()` becomes `pub`.
  - The property loop matches `Value::Text` for `File|Image` and every entry of `Value::List` for
    `Attachments`.
  - `missing_files()` and `referenced_files()` keep their behavior on the owned fields.
- `crates/core/src/csv.rs`: `parse_cell` `Attachments` reads a JSON array of paths
  (`serde_json::from_str::<Vec<String>>`); export already writes lists as JSON via `cell`.
- Fixtures:
  - `crates/core/tests/fixtures/property_photos.yml`:
    `schema: 6`, `key: photos`, `name: Photos`, `format: attachments`.
  - `object_files.md` gains a `photos:` list with two valid paths (a `.png` and a `.jpg`, both 64
    lowercase hex directories); `room: study` stays.
  - Every fixture's `schema: 5` becomes `schema: 6`.
  - `invalid/schema_6.md` becomes `invalid/schema_7.md` with `schema: 7`.
  - `crates/core/tests/roundtrip.rs`: `current()` matches `"schema: 6"`; expected names include

    `an_object_files_fixture…` test asserts each `photos` entry satisfies `is_file_path` and the
    `.jpg` satisfies `is_image_path`.
- Grep `schema: 5` and `FORMAT_VERSION` across `crates/`; every test literal becomes 6. Semantic
  cases (a schema-4 file upgrades to 6) stay.

**Acceptance:** a schema-5 space loads and rewrites as schema 6; `photos: [a, b]` round-trips; a
path outside the grammar, a duplicate path and 201 paths are refused; a missing schema-6 binary
refuses a schema-7 file; `attachments` sorts by basename; a list value appears in

**Tests:** value/validate/index/csv unit cases; roundtrip over the new and updated fixtures.

**Files:** `lib.rs`, `model.rs`, `value.rs`, `validate.rs`, `index.rs`, `csv.rs`, `markdown.rs`

### Checkpoint 2 — Server: labels, CSV paths, the library read

- `crates/server/src/routes/files.rs`:
  - `/api/spaces/{space}/files` becomes `get(library).post(upload)`; the module doc names three
    surfaces.
  - `async fn library` [viewer] returns:
    ```json
    { "items": [ { "path": "files/<hash>/<name>", "name": "<name>", "size": 123,
                   "kind": "image"|"file", "unused": false,
                   "records": [ { "id": "<uuid>", "rev": 3, "title": "Monstera", "icon": "🪴",
                                  "type_key": "plant", "type_name": "Plant",
                                  "field": "photos", "field_name": "Photos",
                                  "trashed": false, "updated_at": "..." } ] } ],
      "total_bytes": 0, "unused_bytes": 0 }
    ```
  - One `with_index` pass collects owned references; `referenced` = every path they name (live and
    trashed). Iterate `store.list_files()` attachments: size from `attachment_len`, name/kind from
    `split_file_path`/`is_image_path`, `unused = !referenced.contains(path)`. Records are deduped by
    object id (first field wins, cover → property → body); `field_name` resolves
    `index.property_def(field)` and falls back to `"Cover"` / `"Body"` / the key, and `type_name`
    resolves `index.type_def(type_key)` and falls back to the key. Sort items by
    lowercased name then path. `total_bytes` sums attachments; `unused_bytes` sums unused ones.
    A referenced path whose bytes are missing never appears.
  - `collect_garbage` needs no logic change; it reads the widened `referenced_files()`.
- `crates/server/src/routes/values.rs`: `File | Image | Attachments` arm; `attachments_label` =
  `""` for empty, `attachment_label` for one, `format!("{} files", n)` for more.
- `crates/server/src/routes/csv.rs` `parse_against`: a `Value::List` on an `Attachments` column
  checks every path with `index.has_attachment`; each missing path is a row error
  `"{path} is not in this space"` in that field.
- Tests beside the existing file-route tests in `crates/server/src/routes/mod.rs`:
  upload two files and an attachments record; `GET /files` returns one item per path with its
  record, kind, size and totals; a viewer reads, a non-member is refused; trashed use is listed
  with `trashed: true` and keeps `unused: false`; an unattached upload is `unused: true` and moves
  `unused_bytes`; GC keeps both attachments of a list; CSV export writes a JSON array and import
  refuses a missing entry.

**Acceptance:** the JSON above is what a seeded record with two list paths and a cover returns; an
unattached upload is the same shape with `records: []` and `unused: true`; a trashed use sets
`trashed: true` and keeps `unused: false`.

## Assumptions & contingencies

- The workspace version is **0.7.0** because the format changes. If the owner decides to call it
  0.6.1, only the three version literals and the changelog heading change; nothing else depends on
  the number.
- Very large attachment lists are capped at 200 paths; if a real space needs more, raise
  `MAX_ATTACHMENTS` and the matching validation message together.
- If `navigator.clipboard.read()` is unavailable in a browser, the `Paste` action shows its refusal
  sentence and file selection/drop remains the path; no fallback API is added.
- If a gallery tile's `attachments` cover value holds only non-image files, the tile uses the record
  cover when it has one and the typographic band otherwise.
