# M9.5 — Types at hand and the UX sweep

Target: space schema **8 unchanged**, workspace `0.9.4` (the last `0.9.x` before M10). A web patch:
no `space.yml` key, no server route, no permission change, no dependency. It gives types and
properties one front door, makes a new type or property one action away from every surface, and
closes the interaction defects found by a full-width and phone audit. It also gives the product a
real favicon and install identity. Written 2026-11-27, after `0.9.3`.

**Status: in progress.** Checkpoint 1 (the favicon and install identity) is landed; checkpoints 2–5
remain. The audit below is the one this milestone was written from.

## Why

The type and property library is the app's most important editor, and it is the hardest surface to
reach. The audit below was run against the seeded Garden space at 1440 × 900 and 390 × 844, signed
in as its owner, plus a 320 px sweep and a keyboard pass. Every row is an observation from that run
or from the named source file, not a general impression.

materials, the 44 px touch floor, the table's interaction model, the record's sheet, the day strip,
and the rail's reorder behavior. This is an access and consistency patch, not a visual redesign.

## Locked decisions

1. **The format does not move.** Schema 8, no server route, no `space.yml` key, no new dependency.
   The route stays `/schema`; only the user-facing name changes, so existing links, deep links,
   tests and docs keep working.
2. **One name for the surface: Types & properties.** It is the palette's existing plain-language
   phrase and it names both tabs. The rail, breadcrumb, page title, error subjects, empty states
   and route meta use it. "Schema" survives only in the URL, code identifiers and the developer
   docs, where it is accurate.
3. **One front door per action.** A **New type** control goes to `/schema?new=type`; a **New
   property** control goes to `/schema?new=property`. The page opens the matching tab and the
   create form, moves focus to the first field, and keeps the list visible. `?type=` and
   `?property=` still select an existing definition; `new` wins over a selection and selecting a
   row clears `new`.
4. **Create from where you are.** Home, the rail's Types header, the phone sheet's Types section,
   the palette and quick capture's empty state all offer the same create action. None of them
   invents a second form; they are links into the one schema surface.
5. **Two lists keep two jobs, and the rail says which.** The rail's type row opens the table. A
   pencil beside it, always present on a coarse pointer and on hover/focus otherwise, opens
   `/schema?type=<key>#type-editor` with `aria-label="Edit <type>"`. The schema list row opens the
   editor. The visual difference is the affordance, not a second label vocabulary.
6. **One verb per action.** **New type** and **New property** open a form; the form's submit reads
   **Create type** / **Create property**. The shared manage sheet is **Properties** everywhere; the
   record's link is **Manage properties**, not **Manage**. The library's count says **properties**,
   never **props**. A column panel's **Add property** becomes **New property** so one action has one
   name.
7. **The tabs are tabs.** Roving `tabindex`, `ArrowLeft`/`ArrowRight`/`Home`/`End`, and focus
   follows selection, per the WAI-ARIA tabs pattern. The tablist keeps its current pill styling.
8. **The mark is a ledger cell.** The favicon is a 2 × 2 table: three filled cells and one empty
   cell, with the top-left cell in the space accent. It is the product's own model — type, column,
   row, cell — and stays readable at 16 px. The SVG follows `prefers-color-scheme`; the PNG set is
   the dark mark and is used for the home screen, where the OS owns the background.
9. **No new runtime.** PNGs are generated once from the SVG and committed. No build step, no icon
   package, no external service.
10. **The audit is bounded.** This patch fixes the ledger above. It does not add views, change the
    record layout, restyle the shell, or reopen M9.4's day grammar.

## Gate

Web after every checkpoint: `npm run test:run && npm run lint && npm run typecheck && npm run
build`. Rust only at release, where no Rust source should have changed: `cargo build --workspace &&
cargo test --workspace && cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D
warnings`. The favicon checkpoint additionally checks the built `web/dist` for all six files and
loads the production-shaped page once.

## Manual QA

1. Open `/s/<space>` and click **New type**. The URL is `/schema?new=type`; the Name field is
   focused; Cancel returns to the list without writing.
2. Create **Books** from that form. It is created, selected in the list, and its editor is open at
   `?type=books`. Repeat from the rail **Types** header and from the phone sheet's Types section.
3. Press `Ctrl/Cmd+K` and type `new type`; the **New type** action is first or clearly listed.
   Enter opens the focused form. Do the same for `new property`; the Properties tab opens.
4. From a type page, click **Edit type**. The sheet still opens; **Properties** opens the manage
   sheet; the record's **Manage properties** opens the same sheet.
5. On the schema page, focus **Types** and press `ArrowRight`; **Properties** is selected and
   focused. `Home` and `End` move to the ends.
6. Click the pencil beside a rail type. The schema page opens that type's editor. On a phone, the
   pencil is visible without hover.
7. Open space settings and follow **Types & properties**. It lands on the schema page, not on the
   settings form.
8. Check the browser tab at 16 and 32 px in dark and light. Check `/apple-touch-icon.png` and
   `/icon-512.png` at their native sizes. In a Chromium install prompt, the manifest name and icons
   are present.
9. At 320 px, repeat steps 1, 3 and 6: no horizontal scroll, every target is reachable above the
   dock.
10. As a viewer, the schema page, rail, sheet, palette and settings show no create or edit action.
11. Regression: the type page's create action still opens quick capture for a normal type and
    Today's note for the daily type; the record panel still edits cells; the calendar and schedule
    are unchanged.

The checks this machine cannot perform are a real iOS home-screen install and a physical-device
icon render; the 180 and 512 PNGs plus the manifest are the evidence that stands in.

## Risks

- **The rename could stop halfway.** The route, file names and developer docs keep “schema”; a
  single user-facing string left behind reads as a bug. Checkpoint 2 greps every string and
  checkpoint 4 re-greps after the vocabulary pass.
- **`new` and a selection can fight.** The precedence is explicit: `new` opens the form and clears
  the opposite selection; selecting a row clears `new`; a direct `?type=` with no `new` opens the
  editor. Tests cover each order.
- **The rail row gains a second target.** A nested `<button>` inside a `<Link>` is invalid; the row
  becomes a link plus a sibling button with its own 44 px target. Keyboard order is row, then
  pencil; the pencil's accessible name names its type.
- **The favicon is cached hard.** Browsers cache icons longer than pages; the manual check uses a
  hard reload or a new profile, and the file name stays `favicon.svg` so published links do not
  rot.
- **A 2 × 2 mark can read as an app grid.** The empty cell and the accent fill are what separate it
  from the generic grid; the 16 px check is the gate, not the 512 px render.
- **The properties landing is a judgement call.** Auto-selecting the first property matches Types,
  but it also means the blank editor's create action is only seen on an empty library. The plan
  chooses the match; if the first-property preview reads as a stale selection, the fallback is the
  create action in the empty editor, which checkpoint 2 adds either way.

## Release note

Under **Unreleased**, two highlights: the tab, bookmark and home-screen icon now carry thing's
ledger mark; types and properties have one named front door, and a new type or property opens from
wherever you are. The long tail goes in `details`: the rail and phone sheet create actions, the
palette commands, the settings link, the tab keys, and the vocabulary cleanup.
