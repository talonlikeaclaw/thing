# Milestone 4.4 — usability sweep

**Status: scoped 2026-10-28, not implemented.** This is the v0.4.4 execution spec. Implement
top-to-bottom, one checkpoint per turn, under the delivery protocol in
[`docs/ROADMAP.md`](../ROADMAP.md). Read `docs/ROADMAP.md` first, then this file. M1 is deployed as
`v0.1.0`; M2–M4.3 are landed as `0.2.0`–`0.4.3`. Nothing here re-opens a locked decision.

v0.4.4 is a web-only usability patch after the touch releases. It makes the surfaces a person
touches every day — Schedule, the table, record pages, saved views, the calendar, capture and the
phone column panel — behave the way the screen says they do. It adds **no route, no server field,
no core change, no format change, no dependency and no schema bump**. `FORMAT_VERSION` stays `4`.

The work below was selected from a live audit of the seeded Garden space on the dev stack
(`scripts/seed.sh`), at **1440 × 900 desktop** and **390 × 844 phone**, with CDP touch/coarse-pointer
emulation for the phone states. It is not a wish list: every item in §3 has a measured or
source-verified failure.

## 1. Scope

In scope:

- **Completion and destruction tell the truth and can be undone.** Schedule rows get the Undo that
  the table and record page already have; record-page trash gets the Undo the table already has;
  completion toasts name the record they changed; a successful space deletion stops using the
  refusal toast tone.
- **Schedule is a list you can hit.** The whole schedule row opens the record (the verb button stays
  its own target), the horizon control is labelled and wide enough for a thumb, and the type label
  is the type's name, not `Plant · plant`.
- **Every saved view is reachable on a phone.** The tab strip wraps instead of hiding a view under
  the New view button; the phone's View trigger becomes a named More control that matches the
  desktop overflow.
- **Cards and pickers use display names.** Board and gallery cards stop printing `due_date` and
  `recurrence` as field labels; the gallery cover becomes a designed band instead of a blank one;
  type names replace type keys where the key is standing in for the name.
- **The phone column panel and the import door.** The panel stops printing keys that truncate the
  property name, stops giving desktop-only width advice on a touch screen, and an empty type page
  offers CSV import directly instead of hiding it in View actions.
- **The calendar opens where you are.** The current day is scrolled into view on a phone instead of
  sitting below the fixed bottom bar, and the Today button actually moves to it.
- **Record relations read first.** A relation field shows its current value(s) as chips; the
  search-and-list surface opens only when the user asks for it, so the body is not pushed a screen
  down by an always-open list of up to 500 targets.
- **First-run and quiet loose ends.** A fresh home leads with Types/onboarding instead of an empty
  Recent section; capture asks before discarding a typed draft; a phone shows that the socket is
  offline; the palette stops claiming to search bodies; the accent reset says what it does; the
  last owner's member controls are disabled instead of failing on the server.

Out of scope, deliberately:

- **No search milestone.** Full-text search, backlinks, wiki links and the graph stay in M5. The
  palette keeps its bounded title lookup; only its copy becomes truthful.
- **No in-app password or profile editing.** This is the largest workflow gap found (§7), but it
  needs a server route and a session policy, so it gets its own patch, not a UI sweep. The account
  page stays as it is until then.
- **No offline/PWA/service worker/install prompt/push.** The phone gets a connection indicator, not
  an offline mode.
- **No server, core or format change.** `crates/**` is untouched except the version bump in
  checkpoint 9.
- **No new dependency.** The view wrap, the relation disclosure, the calendar scroll and the capture
  confirm use React, Base UI and the existing sheet primitive.
- **No visual re-theme and no desktop redesign.** The palette, type, density and accent system stay
  as they are. The only card change is the gallery cover treatment.
- **No hiding mono option keys inside select/multi-select lists.** v0.4.3 settled that those keys are
  part of the product's signature. This patch removes keys only where they are a *duplicate of, or a
  substitute for, the display name* — board/gallery field labels, `Plant · plant`, `Chore · chore`,
  `due_date · required`, and type keys used in place of type names.
- **No relation-picker server search.** The field still loads the target type's records (bounded at
  500 by `useRelationChoices`); it is collapsed, not re-plumbed. M5 owns search.
- **No performance work.** The bundle stays one chunk; route splitting is a later milestone.

Success is: on a phone, all saved views are visible, the Schedule row opens when tapped anywhere
outside the verb, the calendar opens on today, the Date/Schedule completion can be undone, a
relation field shows its current value without an open list, and the column panel shows full names;
on desktop, the board and gallery read like cards (`Next watering`, `Water every`), the view strip is
unchanged, and every destructive success toast is dismissible; and no new surface leaks a raw
schema key where a display name belongs.

## 4. The rules this patch follows

1. **Undo parity.** Any action that removes something from the screen in one tap — complete, trash,
   duplicate — offers Undo wherever it is performed. A success toast is `plain` and auto-dismisses;
   `danger` is for refusals that need attention.
2. **A target is the whole row, not the text.** On a list row whose only action is “open”, the row's
   content area is the link; the verb/action button stays a separate target. Never nest a button in
   a link.
3. **Names where a person is choosing.** A raw key may appear as a technical echo in the schema,
   CSV, history, table header and record field captions. It may not be the only label of a value
   (board/gallery cards) or immediately repeat a display name (`Plant · plant`, `Chore · chore`).
4. **One control, one label.** A sheet trigger is named for what it contains. If it holds View
   settings, Save as view and Data — CSV, it is More, not View.
5. **No hidden saved state.** A saved view is visible or one obvious tap away at every width. The
   same applies to a relation's current value and the capture draft.
6. **Truthful copy.** The palette says what it searches; the columns panel says what a touch device
   can do; the accent reset says reset.

### Checkpoint 1 — Undo parity and toast honesty

**Files:** `web/src/pages/agenda.tsx`, `web/src/components/object-panel.tsx`,
`web/src/components/type-table.tsx`, `web/src/pages/settings.tsx`.

**Change:**

- `AgendaEntry`'s completion handler reads `{ object: saved, previous }` from
  `useCompleteObject`. Keep the record's title, verb and next due in the message, and add a
  `{ label: "Undo", onAction }` that calls `complete.undo(saved, previous)`, then toasts
  `Completion undone.` and lets the existing space invalidation restore the bucket. Use the same
  failure copy as the table: `Could not undo — …`.
- Use one message shape on every completion surface:
  - with a next date: `Next due ${nextDue} for “${title}”.`
  - without: `“${title}” marked done.`
  The table's `completeRecord` and the record page's `runComplete` adopt the same shape. The record
  page already has Undo; keep it.
- `ObjectPanel.moveToTrash` adds the Undo action using `useRestoreObject` (already exported in
  `api/queries.ts`). On success, toast `Restored “${title}”.`; on failure, `Could not undo — …`.
  The navigation to the type page stays; the toast is global, so Undo still works.
- `SettingsPage.onDelete` uses the `plain` tone for the success message. The delete confirmation
  remains the only warning; the success toast auto-dismisses like every other success.
- Add no new toast variant and no new dependency.

**Acceptance:** On Schedule, completing a plant removes it, names it in the toast, and Undo restores
the row and its due/last values. On a record page, Move to trash offers Undo and the record returns
to its table. Deleting a throwaway space shows a plain toast that leaves on its own. The table and
record-page completion toasts name the record and still Undo.

**Verify:** Live at 390 and 1440: complete, undo, complete again; trash from record page, undo;
delete a scratch space. No server failure state is faked; the undo path is the real mutation.

### Checkpoint 3b — View order (added 2026-10-29 at review)

Scope added after §5 was written, at the owner's request: a type's views were fixed in creation
order, which is annoying in daily use. This is the one place v0.4.4 widens its own §1 rule, so it is
recorded here rather than folded silently into checkpoint 3.

**Files:** `crates/server/src/routes/views.rs`, `crates/server/src/routes/mod.rs` (HTTP test),
`web/src/api/queries.ts`, `web/src/components/views/view-settings.tsx`.

**Change:**

- `POST /api/spaces/{space}/types/{key}/views/{view}/move` with `{ "position": n }` [editor]:
  permutes the type's ordered `views` list, exactly like `option key reorder` does for options.
  `position` is the 0-based slot the view lands in after the write; a position past the last slot is
  a `422` naming `position`, an unknown view is `404`, and the same slot rewrites the file unchanged.
  No format change: `views` is already an ordered list, so `FORMAT_VERSION` stays `4` and no
  fixture changes.
- **The default view owns slot 0.** `default_view` names `views[0]`, so the view that opens the type
  is its first tab: `POST …/views/{view}/default` moves that view to the front, a move may not put
  another view in slot 0 or move the default away from it (`409`, `the default view stays first`),
  deleting the first view promotes whatever is now first, and `parse_type` normalizes a file whose
  default sits elsewhere (`crates/core/src/markdown.rs::default_view_first`). The strip hides the
  arrows on the default tab, and every other tab's first reachable slot is 1.
- `useMoveView(spaceId, typeKey)` takes `{ key, position }` and seeds the type cache from the
  response like every other view write.
- The view strip owns the control, mirroring the space rail: a `Reorder` toggle
  (`aria-pressed`, `ArrowUpDown` → `Check`, label flips to `Done`) turns the strip into an editing
  list where each tab grows up/down arrows labelled `Move {name} up/down`, disabled at the ends. On
  desktop the toggle sits inline at the strip's trailing edge and the reorder row stays one
  scrolling line; on compact both it and `New view` sit in a labelled row directly beneath the
  views, and reorder mode renders one full-width row per view so a long name cannot change the
  column count. `New view` hides while reordering; the form closes when the mode opens. Selection,
  arrow/Home/End keys and the URL stay untouched, so reordering never switches the view.
- `movedViewSlot(views, key, delta)` in `lib/views.ts` returns the target slot or `null` at an end;
  it is unit-tested like `nav-order.test.ts`. View settings keeps rename, default, kind and delete,
  and does not carry a second order control.

**Acceptance:** In the strip, `Reorder` shows arrows on every tab at 390 and 1440; the default's
arrows are disabled and every other view stops at slot 1; moving Watering up puts it second and the
strip re-reads in that order; the order survives a reload and a second member sees it; `Make
default` on a later view moves it to the front and keeps the DEFAULT badge on it; `Done` restores
the plain strip and nothing about the selected view or its URL changed.

**Verify:** Live at 390 and 1440: toggle Reorder, move a view both ways, reload, re-read the strip
and the file; make a later view default and watch it move to slot 0; try moving it up and confirm
the arrows are disabled and the API answers `409`; check the disabled ends; confirm `New view` is
gone while reordering and returns on `Done`.

## 7. Decisions taken while scoping

- **The view fix is wrapping, not a new view-switcher sheet.** Wrapping removes the hidden state
  without adding an overlay or a second navigation model; the tablist keeps its keyboard semantics.
  A space with many views pays vertical space, but no view is invisible. If a real space exceeds
  roughly eight views, a dedicated picker can replace the wrap in a later patch.
- **The More label is used on compact.** The sheet holds View settings, Save as view and Data — CSV;
  “View” is too narrow and its slider icon collides with Filter. The desktop overflow already calls
  the same idea More.
- **Select/multi-select option keys stay.** This is the v0.4.3 settled decision. The new rule only
  removes keys that are a value's only label or a duplicate of the display name.
- **The relation field collapses, but self-relations are not excluded.** The current value remains
  visible; the picker is opened on request. Excluding the current record is a product decision, not
  a layout fix.
- **The gallery cover is tinted, not removed.** The cover is part of the view's configuration; with
  no image format yet, a tinted band with the option label is more honest and more useful than a
  blank rectangle. M6 replaces it with images.
- **The home Recent section is hidden when empty; no server recents.** The browser-local list is the
  existing contract. A server “recently updated” row is a feature, not a tweak.
- **Capture confirms discard; it does not autosave the draft.** The sheet is a quick-capture surface,
  not a document. A confirmation prevents accidental loss without introducing a second draft store.
- **The offline indicator is a dot, not a banner.** A banner would shift the phone header and the
  page; the dot is visible, accessible and does not move the nav actions.
- **The account/password gap is not a v0.4.4 checkpoint.** It needs `POST /api/auth/password`
  (current-password verification, argon2 rehash, session policy) and a UI. It is the top candidate
  for the next patch after this sweep.

2. **Completion wording.** This plan uses `Next due … for “Title”.` and `“Title” marked done.` If
   the type's custom verb should appear in the toast (`Watered …`), the verb grammar needs a past
   tense rule; the button and row already carry the verb.

5. **The completion check in the table.** Use the type's verb as a text action on hover/selection
   instead of a check? This plan leaves it; the row menu and Schedule already name the verb.
