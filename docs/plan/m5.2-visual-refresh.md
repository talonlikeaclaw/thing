# Milestone 5.2 — the visual refresh

**Status: PLANNED 2026-11-03 at workspace `0.5.1`.** This is the v0.5.2 execution spec. It starts
after v0.5.1 is committed; v0.5.1 ships behavior only and deliberately freezes the visual system, so
the two patches do not fight over the same files. No checkpoint has started.

v0.5.1 made the v0.5 surfaces truthful: links in both directions, search that lands on its match,
editor actions without detours, and rename repair. v0.5.2 makes them feel like one instrument. It is
the **second printing of the Nocturnal Field Guide**: the same dark ground, hairline rules, one
accent and dense data, but with a display voice, a real composition for every surface, states that
reward use, motion that explains change, and a phone shell built for a thumb.

This is **amplify hard, not replace**. The world stays — dark field-guide ground, keyed entries,
mono annotations, naturalist's margin. What changes is the craft inside it: Maple Mono for
display, page titles and every annotation, a five-step neutral scale, a selection wash that belongs to the accent, a
cover-sheet space home, a specimen-sheet record, ledger tables, a command-surface palette, and a
phone that feels designed rather than compressed. `DESIGN.md` and `.impeccable/design.json` are
rewritten for v0.5.2, but they describe the same world at a higher resolution.

No format or schema change, no new API read, and no behavior change beyond the visual states this
patch names and the graph destination added in checkpoint 8. One dependency swap:
`@fontsource/maple-mono` (5.3.0) replaces IBM Plex Mono and takes the display role; IBM Plex Serif
is not installed at all.

## 1. Scope

In scope:

- **A real design foundation.** Maple Mono for display, title and every annotation, a documented
  type scale that
  covers display, title, heading, body, small and label; a neutral scale with one new inset step and
  one accent-wash step for selection and match; spacing, radius, control-height and motion tokens;
  focus, hover, active, selected, disabled, loading and error states defined once.
- **A space cover sheet.** The space home becomes a composed page: oversized mono space name,
  a one-line factual summary, the primary actions, a keyed type ledger with counts, a recent
  timeline and the file-backed footer. Navigation gains a clear active marker and a quieter
  all-spaces treatment.
- **A record specimen sheet.** The record becomes the centre of the system: identity and status in a
  header band, a sticky property margin on wide screens, one date grammar, the body at a readable
  measure, links and graph as evidence, history folded below. The repeated mono key under every
  label is removed at a fine pointer; keys remain in the schema editor.
- **Ledger tables and views.** Table headers, row states, pinned title, column rhythm, view tabs,
  filter/sort bar, board/gallery/calendar chrome and the page header all share the v0.5.2
  foundation. No column, sort, filter or width behavior changes.
- **A command surface.** Search/palette, quick capture, sheets, toasts, shortcut sheet and sign-out
  follow one overlay geometry and one type/space rhythm. Motion explains opening, closing and
  result changes.
- **A phone shell.** Bottom nav, top bar, space switcher, save bar, sheets and thumb-reach actions
  are composed for 390 × 844 first; 44 px targets and 16 px inputs remain non-negotiable. The save
  bar is quiet when clean and expands only when there is something to save.
- **The quiet surfaces.** Schema, members, settings, trash, auth, join, changelog and not-found
  inherit the foundation: section rules, field rhythm, list rows, empty states and one primary
  action.
- **Visual QA and release.** Every surface captured at 390/1024/1440 in both schemes and both
  handedness modes; contrast and focus audited; reduced motion exercised; docs and version updated
  to `0.5.2`.

Out of scope, deliberately:

- **No behavior change.** Routes, formats, permissions, search semantics, link resolution and
  editor commands stay as v0.5.1 leaves them. A visual refresh that changes a workflow is a
  separate checkpoint or a separate release.
- **No new world.** The ground stays dark green-black; light stays bone; the accent stays one of the
  six shared presets; no gradients, no glass, no shadows, no cards, no second accent, no
  illustration set, no emoji as interface iconography.
- **No new icon library.** Lucide stays, at the same line weight; the type and record icons remain
  user-authored.
- **No new state management or data read.** Counts and recents come from the existing reads. If a
  cover-sheet line needs a number the API does not have, the line is cut rather than inventing a
  read.
- **No WYSIWYG or new editor blocks.** The writing surface keeps its textarea and the twelve
  round-trippable commands.
- **No dark/light rewrite.** Both schemes are retuned, not replaced; the accent contrast test stays
  the gate.
- **No attachments or images.** M6 owns files, covers and a file property.

Success is: a stranger can tell the space home, record, table and palette belong to the same product
without reading a label; the space name reads as a cover, not a heading; a record at 1440 is one
specimen sheet with a property margin and one date grammar; a table scans as a ledger with a pinned
title; the palette feels like a command surface, not a small dialog; the phone save bar is invisible
when there is nothing to save; every interactive state is visible without hovering; motion is
present and explainable, and absent under reduced motion; no format or API changed; and the only new
route is the graph destination in checkpoint 8.

## 3. What the starting state does

The audit that produced this plan was run on 2026-11-03 against the built SPA and the seeded Garden

  empty band below; the type rows carry a `SCHEDULED` label but no count in the primary column; the

- The record at 1440 is a single 1080 px column: a 26 px title, a mono metadata line, a schedule
  strip, six full-width property blocks with 10 px key echoes, a 352 px editor, a links section and

- The type table has a dense 11 px header, a title column that scrolls away, quiet row actions and

- The palette is a 452 px dialog with a 15 px input, a result row, a snippet and a footer count; the

  persistent `SAVED / Save` bar above the bottom nav.
- `globals.css` has one entrance animation (`settle`, 260 ms) and colour transitions on controls;
  there is no page, view-switch or result-change motion, and no type scale.

## 4. The rules this patch follows

1. **Same world, higher resolution.** The brief is the existing Nocturnal Field Guide. A decision
   that requires a different palette, a second accent, shadows, cards or a new icon language is out
   of scope. If a surface cannot be improved inside the world, say so and stop.
2. **The display face is the mono voice, not a body face.** Maple Mono is used for the space name,
   page titles, record title and the one pull-quote/empty-state line per surface, at 400 with
   negative tracking and contextual alternates off. Body, controls, tables and prose stay Plex Sans;
   keys, counts, dates and annotations stay the same Maple Mono. A monospaced paragraph is a
   defect.
3. **One accent, one wash.** The shared accent still marks state. A single `accent-wash` tint (max
   12% alpha on ground, contrast-tested) may mark selection, the active row, the search match and
   drag. It is never a decorative panel, never a gradient, never a second accent.
4. **Rules before boxes.** Depth comes from tonal steps and hairlines, not shadows or cards. A
   surface may have a ground and a rule; it does not get a floating rectangle.
5. **The page has a margin.** At `xl`, the space home and record use a real margin column for
   annotations, counts, folios and properties. The margin is information, not decoration; if it has
   nothing to say, it collapses.
6. **Every state is visible.** Hover, focus-visible, active, selected, disabled, loading, empty,
   error and read-only are defined for every interactive primitive before it is used. A control with
   no focus-visible replacement is a defect.
7. **Motion explains, never decorates.** Entrance, view switch, overlay, save state and result
   change may animate; tables, prose and layout do not. Animate `transform` and `opacity` only,
   with explicit properties, 120–240 ms, and a reduced-motion path that is instant.
8. **Behavior is frozen, except the graph destination.** No route, format, API, permission or
   editor command changes. Checkpoint 8 adds one page over the existing space-graph read and one
   navigation entry; nothing else. A visual fix that needs new data is cut or uses an existing
   read; a visual fix that needs any other behavior change is a separate milestone.
9. **Tokens or nothing.** Every repeated size, colour, space, radius, duration or ease comes from
   `@theme` or a documented CSS variable. A one-off stays local and is named in **Decisions taken**.
10. **One primitive per job.** Button, field, menu, dialog, sheet, row, page header, section rule,
    empty state and notice are each defined once in `components/ui/` and consumed. No per-page copy
    of a control.

### 4.1 AGENTS.md and the delivery protocol

`AGENTS.md` is binding in full for every checkpoint. Concretely:

- **The user commits; the agent never does.** No `git add`, `commit`, `tag`, `push`, `stash`,
  `reset` or history rewrite. Leave each checkpoint in the working tree and end with one
  **Proposed commit** line.
- **One checkpoint per turn**, with the full report: **Built**, **Concepts**, **Decisions taken**,
  **Verified**, **Test it**, **Inspect**, **Proposed commit**.
- **Never claim a gate that did not run.** Rust: `cargo build --workspace && cargo test --workspace
  && cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings`. Web:
  `npm run lint && npm run typecheck && npm run test:run`, plus `npm run build` in checkpoint 9.
- **The changelog moves with the user-visible change.** Open `Unreleased` in checkpoint 2, extend it
  through 8, and promote to `0.5.2` in checkpoint 9. Outcomes only; no file or component names, no
  endpoints or schema keys.
- **The docs stay true.** `DESIGN.md` and `.impeccable/design.json` are updated in the checkpoint
  that settles each decision. Checkpoint 9 updates `AGENTS.md`, `docs/ROADMAP.md` and this file.
- **No behavior change hidden in a visual checkpoint.** If a surface needs a new handler, a new
  query or a different rule, stop and ask; that is not this patch.
- **The one dependency is the font.** `@fontsource/maple-mono` is imported for 400 and 500 only and
  `@fontsource/ibm-plex-mono` / `@fontsource/ibm-plex-serif` leave the manifest; no CDN, no second
  family, no icon package.
- **If the plan is silent or wrong in front of the code, stop and ask.**

### 4.2 Impeccable and the visual process

This patch is a design task, so the design skill is used as a process, not a decoration:

- **Checkpoint 1 runs the critique before any token changes.** If the skill's launcher is available,
  run `impeccable context` once, then `critique` over the space home, record, table, palette and
  phone shell, and `audit` for accessibility. If the launcher is unavailable, say so in the report
  and read `PRODUCT.md`, `DESIGN.md`, `.impeccable/design.json` and the critique folder directly; do
  not invent context.
- **Direction before code.** The critique produces a short, written direction: three to five
  concrete moves, the anti-references, and the surfaces that must not change. It is appended to the
  new critique file and summarised in the checkpoint report. No pixel is moved before it.
- **Craft floor before edits.** Read the skill's craft-floor reference immediately before the first
  UI edit in each checkpoint. It carries the absolute bans and the reflexes a detector misses.
- **Look at the rendered result at shipping sizes.** Every checkpoint ends with screenshots at
  390 × 844, 1024 × 768 and 1440 × 900, in both schemes, in both handedness modes for changed
  surfaces. Compare against the previous checkpoint's screenshots, not from memory.
- **Detector findings are triaged, not silenced.** A contrast, focus, tiny-type or overflow finding
  is fixed in the checkpoint; a false positive is recorded with the reason.

### 4.3 Handedness and the visual system

`DESIGN.md` and `.impeccable/design.json` are rewritten by this patch. The handedness rules stay:

- **Reading order never moves; thumb actions do.** Page headers, prose, table columns, graph nodes
  and settings rows never mirror. Dialog/sheet closes, action rows and the save bar do.
- **Action rows use `ThumbRow`.** The primary action sits at the thumb edge and moves in the DOM.
- **The phone shell is checked in both modes.** The bottom bar, space switcher, save bar and sheets
  are the surfaces most likely to double-reverse.
- **No visual change may move a control's reading order silently.** If a composition reorders a
  page, the DOM order is updated so Tab and screen-reader order agree.

    `--text-heading` 18/1.35 sans, `--text-body` 15/1.6 sans, `--text-small` 13/1.5 sans,
    `--text-label` 11/0.09em mono; phone display 30/1.08, title 22/1.15. Display and title are
    smaller than the serif scale because Maple Mono advances at 0.6em and a serif at about 0.5em:
    the same pixel size would read a fifth wider.

    `--color-accent-wash` (the sole tint, max 12% alpha, derived per accent and scheme);
    `--color-line` stays the hairline, `--color-line-strong` the hover.

  - control heights: 36 fine, 40 standard, 44 coarse; fields 40 fine / 44 coarse.

    `--duration-base` 180ms, `--duration-slow` 240ms.
- Define the primitive states once in `controls.tsx` / `sheet.tsx`: button variants (primary, ghost,
  quiet, destructive), field frame, focus-visible ring (2 px accent, 2 px offset), hover, active,
  disabled, loading, selected, error. No page defines its own button or input.
- Extend `lib/accent.ts` / `accent.test.ts` with the wash: every accent's wash at 12% must keep body
  text at ≥4.5:1 in both schemes; the wash is never used behind primary text.
- Rewrite `DESIGN.md` and `.impeccable/design.json` for the v0.5.2 foundation: type roles, the mono
  voice, the ligature rule, the five-step neutral, the one wash, the margin, motion and the state
  table. Keep the existing world statement and the "one accent" rule.
- No page composition changes in this checkpoint. The app must look coherent-but-unfinished: same
  layouts, new primitives.

**Acceptance:** The app still behaves exactly as v0.5.1; Maple Mono loads, is used for every mono
role and is applied to display nowhere except where the new tokens are explicitly used; Plex Serif
is gone from the manifest and the bundle; every button and field uses the shared states; the accent

## 7. Decisions taken while scoping

- **Amplify hard, same world.** The user chose the incumbent field guide over a replacement world.
  The second printing adds a display voice, a larger type contrast, a real margin and motion; it
  does not add a new palette, shadows, cards or a second accent.
- **The display face is Maple Mono, and the mono role is the same face.** The user asked for Maple
  Mono as the title face, so the patch promotes the mono to a voice instead of buying a third
  family: wordmark, space name, page titles and record title are the same face as the keys, at 400
  with negative tracking. IBM Plex Serif is retired.
- **The body face stays IBM Plex Sans.** It already carries every sentence in the product and its
  squarish humanist bowls give the soft mono enough contrast without a second new dependency. A
  neutral grotesque (Inter, Geist) would read colder and more generic; a sturdier public-sector
  neutral (Public Sans) or a tighter contemporary (Instrument Sans) are the only alternatives worth
  a later test.
- **The accent wash is the only tint.** Selection, active rows, search match and drag need a
  background; a 12% accent wash is the smallest truthful way to provide it. It joins the existing
  contrast test and is never decoration.
- **The record margin is editable, not a second mode.** The property controls stay live in the
  margin. A read-first/edit-later split is a different interaction model and not worth the risk in a
  visual patch.
- **Dates get one visible grammar.** The native picker remains for input and platform familiarity,
  but the field's visible text is formatted by the app, so the record never shows three date
  grammars. A custom calendar is deferred.
- **No new route or read for the cover sheet.** Counts and recents come from existing reads; any
  line without data is cut. The graph page in checkpoint 8 is the patch's only new destination, and
  it reuses the existing space-graph read.
- **No page transitions between routes.** The settle entrance and overlay motion are enough; a
  router transition risks layout jank and reduced-motion bugs. View switches and result changes may
  animate.
- **The folio is typographic.** Section/specimen numbers and marginalia are mono annotations, not
  new icons. If a surface has nothing to annotate, the margin collapses.

## 8. Open questions for review

1. **Should the display mono also set table/gallery card titles?** The plan uses it for page and
   record titles and one empty-state line; card titles stay sans to keep dense scanning. If the
   gallery feels flat, a mono card title is a checkpoint 4 decision.
2. **Should the space cover sheet include a "last edited" line?** The current reads expose record
   updates; a space-level summary would need a new read. The plan omits it rather than adding one.
3. **Does the phone save pill conflict with the toast stack?** Both sit bottom-right; the plan
   offsets the pill above the toast stack and hides it while a toast is present. If that feels
   noisy, the pill can move to the top bar.
4. **The physical-iPhone gate** from v0.4.3 remains open. No keyboard or thumb-reach claim in this
   patch is hardware-backed until it runs.
