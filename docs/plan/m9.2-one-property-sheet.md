# M9.2 — One property sheet

Target: schema 8 unchanged, workspace `0.9.1` unchanged. A web-only patch that lands between
checkpoints 8 and 9 of [`m9.1-property-depth.md`](m9.1-property-depth.md), because checkpoints 9–12
add controls to the same authoring surfaces and would otherwise be moved twice. Written
2026-11-16.

**Status: landed at `0.9.1` on 2026-11-22.** No format, route, permission or dependency change.

## Why

Two objects — a property definition and a type's membership in it — are edited from six places,
and only one of them can set the membership fields the model already has:

| Surface | Opened from | Writes |
|---|---|---|
| `schema/type-editor.tsx` | Schema → Types | the whole type, including a membership draft with Required and Default |
| `manage-properties.tsx` | Type page **Properties**; record **Manage** | memberships: search, remove, reorder; Edit opens the property editor, Add opens the add sheet |
| `add-property.tsx` | Manage sheet; table header; column panel | property + member `{required:false}` + view column, as four staged calls |
| `schema/property-list.tsx` | Schema → Properties | a space-level property, no type |
| `schema/property-editor.tsx` | Schema → Properties; Manage **Edit** | property-level fields, rename, delete, promote |
| `views/column-panel.tsx` | Type page → View → Columns | per-view columns only (correctly separate) |

`required` and `default` live on the membership (M9.1 decision 2), so the type editor can set them
and the type page's Properties sheet cannot; a property added from the table gets
`required: false` with no way to change it without leaving the table. The type editor and the
Properties sheet are the same list in two places, with different powers.

## Locked decisions

1. **One editor for a property and its membership.** `PropertyEditorForm` (and the sheet that wraps
   it) gains an optional type context. With it, the form renders an **On this type** group holding
   Required and Default, and one Save writes both. Without it — the schema page's Properties tab —
   the form is exactly what it is today.
2. **One Save, two writes, in order.** The property is written first (only when its own fields
   changed), then the type (only when the membership changed). A failure leaves the sheet open and
   names the stage that failed; a retry writes only what is left. Both are existing routes.
3. **The type editor stops editing memberships.** It keeps the type's own fields and shows its
   properties read-only with their Required/Default summary, plus **Manage properties**, which opens
   the same sheet the type page opens. Its PATCH no longer carries `properties`, so a stale type
   draft can never clobber a membership written from the sheet.
4. **The add sheet asks for the membership as it creates it.** Required is offered for every stored
   format; Default only where a value can be chosen before the property exists — a `select`,
   `multi_select` or `relation` has no options or targets yet, so it says to set the default after
   the property exists. The member stage sends what the form holds.
5. **The membership group is bare, not a disclosure.** The sheet and the add form are already the
   one place; the type editor no longer mounts the controls at all, so the `<details>` wrapper is
   removed from `MembershipDefault`.
6. **The zone comes from the space.** `MembershipDefault` reads `useSpace(spaceId)` for the date
   field's zone instead of threading a prop through every caller.
7. **The schema page's Properties tab still creates without a type.** A space-level property has no
   membership, so its create form and editor keep no On-this-type group.

## The sheet

```ts
interface PropertyEditorFormProps {
  spaceId: string;
  property: PropertyDef;
  types: TypeSummary[];
  library: PropertyDef[];
  canEdit: boolean;
  /** The type whose membership is being edited; absent on the schema library. */
  type?: TypeDef;
  /** The membership to edit; present exactly when `type` is. */
  member?: TypeProperty;
  headingId?: string;
  onRenamed?: (key: string) => void;
  onDeleted?: () => void;
}
```

- **On this type** (only with `type` and `member`): Required, Default (the record page's own
  `PropertyField`), Clear, and the sentences that explain a calculated or unique property.
- Dirty is `propertyDirty || membershipDirty`; Save writes the property then the type; the guard
  and the sticky bar cover both.
- A saved membership is adopted from the returned type, so a server-side normalisation (an empty
  default dropped) shows immediately.

## What each surface becomes

- `manage-properties.tsx`: a row's **Edit** opens the sheet with `type` and that row's member. Search,
  reorder, remove and Add stay where they are.
- `type-editor.tsx`: type fields only; a read-only property list (`Required · Default x` per row) and
  **Manage properties** opening `ManageProperties`. No membership state, no `invalidDefaults`, no
  inline Add property.
- `add-property.tsx`: an **On this type** group after the format and validation fields; the member
  stage sends `{key, required, featured, default}`.
- `property-list.tsx` and `pages/schema.tsx`: unchanged, except that the editor they render can now
  receive a type context (they do not pass one).
- `membership-default.tsx`: the bare group; `defaultApplies` and a new `defaultPickable(format)` for
  the add sheet's gating.

## Tests

- `property-editor.test.tsx`: an unrelated property rename does not rewrite the membership; a
  membership edit writes the whole list with the new value and leaves the property alone; a property
  edit leaves the membership alone; a membership refusal shows the server's sentence.
- `manage-properties.test.tsx`: Edit opens the sheet with the row's member; a saved membership
  updates the row's summary.
- `type-editor.test.tsx`: rewritten — the type save carries no `properties`; the property list shows
  the membership summary; **Manage properties** opens the sheet.
- `add-property.test.tsx`: a new text property with Required and a default sends both in the member
  stage; a new select offers no default editor.
- `membership-default.test.tsx`: the bare group (no disclosure), the gating, and Clear.
