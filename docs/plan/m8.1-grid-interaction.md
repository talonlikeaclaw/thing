## Context

The type page's table (`web/src/components/views/table-view.tsx`) is already a keyboard grid: one
roving `active` cell (`{row, col}`), arrow and `h`/`j`/`k`/`l` movement, `Enter` to open the active
cell, `x` to select a row, `/` to reach search, `Escape` to clear. `role="grid"` and
`aria-rowcount`/`aria-colcount` are set; rows carry `aria-selected` for the bulk selection.

What it cannot do:

- **Tab is not traversal.** Only the active cell's `<td>` is tabbable as a cell, but every cell
  button (`PropertyCell`, `TitleCell`) is its own tab stop, so `Tab` walks control-by-control
  instead of cell-by-cell, and the active row's rail controls join the walk.
- **There is one cell of context.** `active` is a single position; there is no anchor, so a reader
  cannot mark a rectangle of cells, and `Shift` does nothing.
- **Nothing leaves the page as data.** The CSV export is a whole type at once; copying four cells
  out of a table into a message or a document is impossible without retyping.
- **The table shows rows but never their numbers.** Whether a filtered page of 50 expenses totals
  what the reader expects is only answerable by hand or by exporting.

M8.2 (trust and bulk writing) already plans TSV paste, clear-range and bulk transforms; all three
need a rectangle concept. M8.1 therefore lands the selection model itself, read-only, and stops
there. Charts, pinned aggregations and conditional formatting belong to M10 and are not here.

## Locked decisions

1. **Schema 7, workspace `0.8.1`. No server, route, read, permission or dependency change.** The
   grid reasons entirely over the rows the list route already returned. A viewer gets the same
   selection, copy and footer; none of them write.
2. **The data columns are title plus the view's columns, and they are contiguous.** The checkbox
   column, the add-property header cell, the tail spacer and the action rail are controls, never
   data. A range, a copy and a footer cell exist only for data columns.
3. **One roving tab stop in the grid body.** Only the active cell's `<td>` is tabbable among body
   cells; `PropertyCell` and `TitleCell` display buttons take `tabIndex={-1}` and are opened with
   `Enter` (which already clicks them). Header controls, the row checkboxes and the rail keep their
   existing tab stops so keyboard row selection and record actions do not regress.
4. **Tab is spreadsheet traversal, not the ARIA grid's leave-the-grid key.** `Tab` moves to the
   next data cell, wrapping to the next row's first data cell; at the last data cell it is not
   intercepted, so the browser moves focus out of the table. `Shift+Tab` is the exact reverse. This
   is a deliberate deviation from the APG grid pattern, which the roadmap asks for. The branch runs
   only when the event originates inside a data cell (`closest("[data-grid-cell]")`), so the
   header's sort and resize controls, the checkbox column and the action rail keep their native
   `Tab` order; the data `<td>` carries `data-grid-cell` beside `data-cell`.
5. **Tab traversal is a view-mode binding.** While a cell editor is open (`isEditableTarget`), the
   grid ignores the key and the editor keeps its current contract: `Enter` commits, `Escape`
   cancels, `Tab` leaves via the input's blur and commits. The plan does not invent a second commit
   path through `Tab`.
6. **Selection is an anchor and a focus over data cells.** A range is the normalised rectangle
   between them; a plain move or click collapses it. `Shift` extends it from the anchor. The active
   row's `x` selection and the cell range are independent states and may coexist.
7. **Copy writes what the cell shows, never what it stores.** Every copied cell is the row's
   rendered `label` (or the title), so a relation copies target titles, a select copies option
   names, a file copies its stored name, and a calculated column copies its computed value. Copying
   a single focused cell copies that one label; copying a range copies a header row plus the
   selected rows.
8. **Two copy spellings, one of them on the keyboard.** `mod+C` copies the range as TSV (or the
   single cell as plain text); the range bar offers `Copy` (TSV) and `Copy as Markdown`. TSV is the
   interchange spelling because every spreadsheet and notes app accepts it; the markdown table is
   the writing-surface spelling.
9. **Summaries are client-side, over the displayed rows, and ephemeral.** The footer reads exactly
   the `rows` the table already renders (one page, the active filter, the server's order). It is
   never written to the view, the type or the URL, and there is no server aggregation. The footer
   says so in words when more rows exist.
10. **Aggregation is defined per format, not per column.** Each format has one short footer text and
    one full sentence; a calculated column aggregates by its result format. The rules are locked in
    the table below, so an implementation cannot choose a different average precision per column.
11. **The range is a fine-pointer and keyboard surface.** There is no drag-select and no touch
    gesture in this checkpoint; a phone sees the footer and the existing phone table unchanged. A
    range that exists when the viewport shrinks keeps working.
12. **No new visual token.** The range reuses the accent wash, the active cell an inset accent ring,
    and the footer the raised band and the mono tabular voice. `DESIGN.md` gains the grammar; the
    token table does not change.

## The grid model

### Columns

`web/src/lib/grid.ts` (new, pure) owns the shapes the table and the later writing patch share:

```ts
/** One data column, in view order: the title first, then the view's properties. */
export interface GridColumn {
  /** `model::TITLE_KEY` ("title") or a property key. */
  key: string;
  /** The header's display text; the copy header and the footer sentence use it. */
  label: string;
  /** Absent for the title and for a view column whose property no longer exists. */
  format?: PropertyFormat;
}

/** A position in the data grid: row index and data-column index. */
export interface Cell {
  row: number;
  col: number;
}

/** An inclusive rectangle over data cells, already normalised. */
export interface Range {
  top: number;
  left: number;
  bottom: number;
  right: number;
}
```

The table builds `GridColumn[]` as `[{ key: "title", label: "Title" }, ...view.columns mapped to
{key, label: property.name ?? key, format: property.format}]`. The DOM column of data index `i` is
`titleCol + i`; the data range is `[titleCol, titleCol + columns.length]`. Those two functions stay
in `table-view.tsx`; the module never learns about select or rail columns.

### Cell math

`lib/grid.ts` exports, with unit tests:

| Function | Contract |
|---|---|
| `sameCell(a, b)` | Identity, null-safe. |
| `clampCell(cell, rowCount, columnCount)` | Saturates both axes; a zero-row grid returns `null`. |
| `stepCell(cell, rowDelta, columnDelta, rowCount, columnCount)` | Existing `move` semantics: clamp, never wrap. |
| `tabCell(cell, firstDataCol, lastDataCol, rowCount, backwards)` | The next/previous data cell, wrapping by row; `null` at the boundary so the caller leaves the default `Tab` alone. A cell on a control column enters the data grid at the nearest edge in the requested direction. |
| `normalizeRange(anchor, focus)` | Inclusive `Range` from any two cells, in either order. |
| `rangeContains(range, cell)` | Inclusive containment. |
| `rangeSize(range)` | `{ rows, columns, cells }`. |
| `rangeCells(range)` | Row-major `Cell[]`; the later paste path iterates this. |

`tabCell` is the only place that knows the data columns are contiguous. `stepCell` keeps today's
behaviour, including movement into control columns, so the existing path to the action rail and its
`Open record` link survives.

### Keyboard map

Handled in `onGridKeyDown` (the scrollport's one listener), after the existing
`defaultPrevented`/`isEditableTarget` guard:

| Key | Behaviour |
|---|---|
| `↓` / `k` | Next row, same column. Collapses the range. |
| `↑` / `j` | Previous row. Collapses. |
| `→` / `l` | Next column, including control columns at the edges. Collapses. |
| `←` / `h` | Previous column. Collapses. |
| `Tab` | Next data cell; at the last data cell, leave the grid (no `preventDefault`). |
| `Shift+Tab` | Previous data cell; at the first, leave. |
| `Shift` + any movement key | Extends the range from the anchor, clamped to the data columns; never enters a control column. |
| `Enter` | Existing activation: checkbox, record link or the cell's editor. |
| `x` | Existing row selection of the active row. |
| `mod+C` | Copy the range as TSV, or the focused cell's label when there is no range. |
| `Escape` | With a range: collapse it, keep the active cell. Otherwise: clear the active cell and the row selection, as today. |
| `/` | Existing search focus. |

Every new binding is advertised. `lib/hotkeys.ts` adds descriptors to `TABLE_SHORTCUTS` (and
therefore to the `?` sheet while a table is mounted): `Tab` "Next cell", `Shift+Tab` "Previous
cell", `Shift + arrow` "Extend the cell selection", `⌘C / Ctrl C` "Copy the selected cells". The
grid and the sheet keep reading one list, per the existing `TableShortcuts` contract.

### Pointer

- A data cell's `pointerdown` makes it the active cell and collapses the range, so the active cell
  follows the mouse even though the focus lands on the inner button.
- A data cell's `click` with `Shift` extends the range from the anchor and is captured on the
  `<td>` with `preventDefault`/`stopPropagation`, so the cell's editor never opens.
- A `Shift` click with no anchor sets the anchor to the clicked cell and selects one cell.
- Control columns ignore both; a click there behaves exactly as today.

### Copy

`lib/grid.ts` exports the text builders; the table owns the clipboard call:

```ts
/** The displayed text of one data cell: the title, or the row's label for the key. */
export function cellText(column: GridColumn, row: ObjectSummary): string;

/** Header labels plus one text row per grid row, in view order. */
export function rangeMatrix(columns, rows, range): { header: string[]; rows: string[][] };

export function toTsv(header: string[], rows: string[][]): string;
export function toMarkdown(header: string[], rows: string[][]): string;
```

- **TSV:** cells in order, `\t` between, `\n` between rows, no trailing newline. A tab, CR or LF
  inside a label becomes one space (a spreadsheet cannot quote a tab in TSV, so the copy must not
  create a phantom column). A single-cell copy is the label alone.
- **Markdown:** `| {header} | … |`, a `| --- | … |` separator, then the rows. In a cell `\` becomes
  `\\`, `|` becomes `\|`, CR/LF become `<br>`; leading and trailing whitespace is trimmed. Empty
  cells stay empty.
- **Writing:** `navigator.clipboard.writeText(text)` (the same API the record panel and member
  invites already use). Success: toast `Copied 12 cells.` or `Copied as a markdown table.` Failure:
  toast the refusal, keep the range, never throw. Tests stub `navigator.clipboard`.
- **Guards:** `mod+C` is ignored when an editor has focus, when the active cell is not a data cell,
  and when `window.getSelection()?.toString()` is non-empty (the user is copying selected prose).

### The selection bar

When a range exists, a bar renders **in normal flow between the type toolbar and the table card**
(not as an overlay, so it cannot collide with the floating bulk bar):

```
12 cells · 3 rows × 4 columns                    [Copy] [Copy as Markdown] [Clear]
```

- `role="group"` with `aria-label="Cell selection"`; the count span is `aria-live="polite"`.
- On a phone it wraps; the buttons stay 44 px coarse targets. The range itself cannot be made on a
  touch device, but a bar left over from a resized window keeps working.
- `Clear` collapses the range and keeps the active cell.

### Aggregation footer

`web/src/lib/aggregate.ts` (new, pure):

```ts
export interface ColumnSummary {
  /** The one-line footer text, e.g. "Σ 1,204 · avg 24.08", "9 distinct", "—". */
  short: string;
  /** The full sentence the cell's aria-label carries. */
  long: string;
  /** Filled cells, and the rows the summary covers. */
  filled: number;
  total: number;
}

export function summarizeColumn(
  column: GridColumn,
  rows: readonly ObjectSummary[],
  timeZone: string,
): ColumnSummary;
```

Rules, locked:

| Format | `short` | `long` |
|---|---|---|
| title | `50 rows` | `Title: 50 rows` |
| number | `Σ 1,204 · avg 24.08` | `Amount: 12 of 50 filled; sum 1,204; average 24.08; lowest 3; highest 90` |
| date | `Mar 3 – Nov 9` | `Due: 12 of 50 filled; earliest Mar 3, 2026; latest Nov 9, 2026` |
| datetime | same, earliest and latest in the space's zone | same |
| checkbox | `7 of 12 checked` | `Watered: 12 of 50 filled; 7 checked` |
| text, url, email, select, multi_select, list | `9 distinct` | `Room: 12 of 50 filled; 9 distinct values` |
| relation, attachments, recurrence, file, image | `12 filled` | `Attachments: 12 of 50 filled` |
| anything with no filled value | `—` | `Amount: none of the 50 rows have a value` |

- Numbers use the reader's locale with at most two fraction digits
  (`Intl.NumberFormat(undefined, { maximumFractionDigits: 2 })`); a text or select column counts
  distinct **display labels**, case-sensitive; a checkbox counts `true` values; a date compares its
  stored `YYYY-MM-DD` and a datetime its stored ISO string (both sort lexicographically).
- The date/datetime `short` form prints month and day only
  (`Intl.DateTimeFormat(undefined, { month: "short", day: "numeric" })`), joined ` – `; the `long`
  sentence carries the year through `formatDay`/`formatDateTime`. A footer cell is narrow by
  design, so the full sentence is always in the `title` and `aria-label` even when the visible text
  is truncated by the column width.
- A filled cell is one whose `row.values[key]?.label` is non-empty, except a checkbox, whose value
  must be a boolean, and a number, whose value must be finite. `0` and `false` are present values.
- A calculated column aggregates by its result format exactly like a stored one.
- The footer is a `<tfoot>` row inside the grid: one cell per data column in view order, blank cells
  for the checkbox, add-property, tail and rail columns, the same colgroup so it aligns and scrolls
  horizontally with the table. Its cells are sticky to the bottom of the desktop scrollport
  (`position: sticky; bottom: 0`, opaque `--color-surface`, one `rule` top border). In an engine
  without sticky `tfoot` it simply remains the last row; nothing else changes. While the bulk
  editor is open (`bulkOpen`, which already reserves a tall bottom band), the footer drops its
  sticky offset and stays the last row: the selection band owns the bottom edge.
- Each footer cell is `aria-readonly`-like static text; its `aria-label` is the `long` sentence and
  its visible `short` text is `aria-hidden`, so a screen reader hears one clean sentence. The footer
  row is counted in `aria-rowcount` as the last row.
- Under the table (beside the existing "Scroll sideways" hint), one muted line states the scope:
  `Summaries cover the 50 rows shown, not all 340.` when `total > rows.length`, otherwise
  `Summaries cover all 12 rows.` This is the honesty clause: the footer never implies it summed the
  whole view.
- The footer renders for every table with at least one row, viewer or editor, desktop or phone.

### Visual and accessible grammar

- **Active cell:** a 2 px inset `var(--color-accent)` ring, drawn with an inset box-shadow so the
  sticky header and the card's clip cannot cut it. It is visible in both schemes and on the accent
  wash.
- **Range:** the existing selected-surface mix (`accent 12%` over `--color-surface`) on every cell
  in the rectangle; the anchor cell additionally carries the 2 px ring, the focus cell a 1 px ring.
  No new colour, no animation.
- **Row selection and range** may overlay; the result is the same wash, which is acceptable because
  the two states answer different questions and the bar names the range's size.
- **Screen readers:** data cells get `aria-selected={inRange}` only while a range exists; the live
  region announces `3 rows by 4 columns, 12 cells selected` when the range changes and the copy
  result when it finishes. Row `aria-selected` keeps meaning the bulk selection.
- **Reduced motion / contrast:** no motion is added; the ring and the wash are token colours already
  contrast-tested in `DESIGN.md`.

## Assumptions & contingencies

- **Computed columns are already materialized** in `rows[].values` by M8's server projection, so the
  footer needs no evaluator; if a real read ever omits a computed key, the footer shows `—` for it
  rather than calling the server.
- **The page is the summation scope.** A reader who expects the whole filtered set will see the
  scope line and the paging line; a server-side aggregate is a M10 concern, not a silent change
  here.
- **Clipboard permissions vary.** A refusal is a toast, never an exception and never a lost
  selection. `document.execCommand` is not a second spelling.
- **Sticky `tfoot` degrades.** If a target browser does not pin it, the footer is the last table
  row; no alternative footer is built.
- **No physical touch device is attached.** Range selection is not offered on touch; the phone
  release check is emulation plus measured DOM, and the v0.4.3 physical-iPhone gate remains open.
- **The plan may meet a Base UI detail** (a popover swallowing the click capture, a focus quirk).
  Settle it in place and record it under **Decisions taken**; do not change the selection model.

## What M8.2 inherits

M8.2's TSV paste, clear-range and bulk transforms build directly on `Range`, `rangeCells`,
`cellText` and the two encoders: paste parses TSV with the CSV cell rules and writes through the
existing per-record PATCH path, clearing writes `null` for the range's keys, and both require the
undo the checkpoint also adds. The selection model must therefore stay pure, exported and free of
React state; `table-view.tsx` owns only the interaction. M10's persisted aggregations and charts
reuse `summarizeColumn`'s per-format rules over a whole filtered read instead of one page, so the
format table above is the contract they extend rather than replace.
