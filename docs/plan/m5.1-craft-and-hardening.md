# Milestone 5.1 — links, search landing and hardening

**Status: LANDED 2026-11-03 at workspace `0.5.1`.** This is the v0.5.1 execution spec. M5 is
landed at `0.5.0`; the phone-editor and graph fix in `42ed5ad` is committed and promoted with this
patch. Checkpoints 1–6 are implemented; v0.5.1 is not tagged or deployed. The visual system is
unchanged and v0.5.2 owns it.

v0.5.1 is the trust patch: a browser-level test harness for the writing surface, palette and links
panel; links reported in both directions with a complete local graph; search that lands on the
sentence it matched; editor actions that remove the remaining detours; and an explicit, previewed
repair when a rename would strand links. No format or schema change, no new runtime dependency, and
no new route.

**Visual work is not in this patch.** The v0.5.2 spec, `docs/plan/m5.2-visual-refresh.md`, owns the
field-guide amplification: display type, the space cover sheet, the record sheet, table chrome,
overlays, phone shell, settings surfaces and motion. v0.5.1 must not move tokens, change type
sizes, restyle the record page or add motion; it may only render the new link, search and editor
behaviour in the visual system that `0.5.0` already has. The two record-page defects found in the
audit — repeated mono keys under labels and the second date grammar — are v0.5.2 work, recorded
there.

## 1. Scope

In scope:

- **A test harness for the interactive surfaces.** Component tests over the real components with
  the installed Testing Library and jsdom: the writing surface, the command palette and the links
  panel. The existing `lib/*.test.ts` suite stays; this adds the layer it never had. No Playwright,
  no new dependency, no CI job beyond the existing `npm run test:run`.
- **A seeded audit with a written ledger.** The Garden space is driven at 390 and 1440 in both
  schemes and both handedness modes; every defect found gets a file/line, a severity and either a
  fix in this patch or an explicit deferral. The audit is recorded under `.impeccable/critique/`.
- **Links in both directions.** A record read with `with=links` gains `links_to`: resolved outgoing
  relation targets and resolved outgoing mentions, each with the target's type, title and icons.
  The Links panel gains a `Links to` group, the local graph gains outgoing relation edges, and the
  graph is shown whenever either direction has a row. The current “No links yet” on a record that
  links out is false and is removed.
- **Search lands on the match.** Opening a record from a search result carries the query, marks
  every occurrence in the rendered body, and scrolls the first one into view. The palette's result
  count uses the singular.
- **Editor craft.** A heading menu for H1–H3, paste-a-URL-over-a-selection, tapping rendered prose
  to enter the editor, and creating a missing record from `[[type/Title]]` completion.
- **Rename link repair, explicit and previewed.** When a title change would strand mentions, the
  save offers a dialog that lists the affected records and rewrites only the links that resolved to
  this record. Cancel renames without touching other files. No automatic rewrite, no silent
  re-pointing, no new route.
- **Version, docs and release.** Workspace and web at `0.5.1`; the `Unreleased` entry promoted and
  extended; `AGENTS.md`, `docs/ROADMAP.md`, `DESIGN.md` and `.impeccable/design.json` true to the
  new link/search/editor behavior; full gates and an honest device-pass note. `DESIGN.md` records
  only behaviour that is new here; the visual system itself stays as `0.5.0` left it.

Out of scope, deliberately:

- **No format or schema change.** `FORMAT_VERSION` stays `4`; no object file gains a key; no new
  revision action. `links_to` is a read projection, not stored data.
- **No new route and no new dependency.** The server read gains one field; the rename repair is
  client-orchestrated over the existing `PATCH`. The heading menu uses the existing Base UI
  Popover, and the test harness uses the installed Testing Library.
- **No Playwright or Cypress.** The audit is a real browser pass plus component tests. A permanent
  end-to-end runner is a later infrastructure decision, not a patch feature.
- **No automatic link rewriting.** Repair only happens behind the dialog, only for records the
  preview listed, and only for links that resolved to the renamed record before the rename. A
  conflict is skipped and reported; it is never retried silently.
- **No rename of type keys.** Type keys are schema identifiers; link repair is about a record's
  title.
- **No WYSIWYG, tables, callouts, to-dos or dividers in the editor.** Slash commands stay the
  twelve the current markdown can round-trip.
- **No search operators, type filter UI or saved searches.** The existing `q` search read is
  unchanged.
- **No visual redesign or polish.** Tokens, type scale, spacing, control styling, motion, the
  record sheet, palette width, phone save bar and empty-state composition are v0.5.2. This patch
  adds only the controls and states its new behavior needs, drawn with the existing tokens.
  The repeated mono keys under record labels and the date-format split stay as they are.
- **No attachments or images.** M6 owns files, covers and a file property.

Success is: a component test fails when the slash menu stops opening at a line start, when a search
result loses its query on the way to a record, or when the Links panel drops an outgoing relation; a
record that points at another shows that target under `Links to` and draws it in the local graph;
searching for a body word and opening the result lands with the sentence marked and in view; typing
`[[plant/New fern` offers to create the record and inserts the resolved link; and renaming a record
with two inbound mentions offers to update them, leaving two new revisions and no dotted links. The
visual system is unchanged from `0.5.0`.

## 4. The rules this patch follows

1. **A read projection is not a format change.** `links_to` is computed from the index at read time.
   Nothing is written to an object file, and no cache is introduced.
2. **One edge, one row.** An outgoing fact is either a relation row (source property named) or a
   mention row (target named), never both for the same target-property or target-mention pair.
   Incoming rows keep the existing rule that a relation and a mention are different facts and may
   both appear.
3. **The graph shows what the panel lists.** If a row is in `Links to` or `Linked from`, the local
   graph has the corresponding edge. If the graph draws an edge, the panel can explain it.
4. **Search state travels in the URL.** The query that opened a record is `?q=`, so Back, refresh
   and a copied link all land on the same highlighted sentence. The query does not alter the
   record or its history.
5. **Completion creates only when the type is known.** A `[[` fragment without a valid `type/`
   prefix stays a search; a fragment with one offers `Create <title>` for that type. Nothing is
   created on a plain title fragment, because guessing the type is a silent schema decision.
6. **Repair is previewed, explicit and best-effort.** The rename dialog names every source before
   any write. Confirming renames first, then rewrites each source with its own `rev`; a source that
   changed in between is skipped and reported. No rollback is promised; revisions are the audit
   trail. Cancelling is exactly the old rename.
7. **The visual system is frozen for this patch.** Use the existing tokens, type sizes, hairlines,
   one accent and IBM Plex Sans/Mono exactly as `0.5.0` left them. A new control may be added, but
   it is drawn with existing primitives; no new token, font, size step, shadow or motion belongs
   in v0.5.1. The v0.5.2 spec owns every visual change.
8. **No layout reads in render.** The match scroll and the preview-tap caret use refs/effects after
   paint, not `getBoundingClientRect` during render.
9. **One implementation per behaviour.** The link parser, the mention rewrite, the match-range
   helper, the plural helper and the local edge builder are each defined once and unit-tested; the
   panel, graph and editor consume them.

### 4.1 AGENTS.md and the delivery protocol

`AGENTS.md` is binding in full for every checkpoint; read it before starting one and follow it
where this file is silent. Concretely:

- **The user commits; the agent never does.** No `git add`, `commit`, `tag`, `push`, `stash`,
  `reset` or history rewrite. Leave each checkpoint in the working tree and end with one
  **Proposed commit** line.
- **One checkpoint per turn**, with the full report: **Built**, **Concepts**, **Decisions taken**,
  **Verified**, **Test it**, **Inspect**, **Proposed commit**.
- **Never claim a gate that did not run.** Rust: `cargo build --workspace && cargo test --workspace
  && cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings`. Web:
  `npm run lint && npm run typecheck && npm run test:run`, plus `npm run build` in checkpoint 6.
  HTTP behavior is pinned in `routes::tests` over the real router; web helpers and components get
  colocated tests.
- **The changelog moves with the user-visible change.** The existing `Unreleased` entry is extended
  by each user-visible checkpoint and promoted to `0.5.1` in checkpoint 6. One change per sentence,
  outcomes only, no file or component names, no endpoints or schema keys.
- **The docs stay true.** Checkpoint 6 updates `AGENTS.md`, `docs/ROADMAP.md`, this file, and the
  behavioral paragraphs in `DESIGN.md` / `.impeccable/design.json` for the new links, match marker
  and editor actions. It does not change the visual system; that is v0.5.2.
- **No new dependency and no workspace-wide change.** The test harness uses what is installed. The
  heading menu uses the Base UI Popover already used by `snooze-menu.tsx` and `object-panel.tsx`.
- **If the plan is silent or wrong in front of the code, stop and ask.** Do not narrow scope
  quietly.

### 4.2 Handedness and the visual system

`DESIGN.md` and `.impeccable/design.json` are normative throughout. v0.5.2 updates them; this patch
only adds behavior in the existing system. For every surface this patch touches:

- **Reading order never moves; thumb actions do.** Rename dialog actions, palette close and the
  preview edit affordance follow `useHandedness()`; prose, properties, table columns and graph nodes
  never mirror.
- **Action rows use `ThumbRow`.** Do not hand-roll a conditional `flex-row-reverse`.
- **The graph keeps its handedness rule.** New outgoing edges do not change node positions, labels
  or the left/right-handed control row.
- **Every checkpoint is checked at 390 and 1440 in both schemes and both handedness modes** for the
  surfaces it touches. A failure here is a checkpoint failure.
- **No visual decisions.** If a new control needs a size that is not already used, reuse the nearest
  existing primitive rather than inventing a step. A visual idea belongs to v0.5.2.

### Checkpoint 2 — Links in both directions

**Files:** `crates/core/src/index.rs`, `crates/core/src/links.rs` if a shared row type is needed,

**Change:**

- Core gains `outgoing_relations(id) -> Vec<RelationTarget>` (or equivalent) beside
  `outgoing_links`: every live target named by a relation property on the record, deduped by
  `(target, property)`, in property-key then target-title order. It reads the same
  `PropertyFormat::Relation` and `relation_targets` rules as `backlinks_of` and `graph()`; do not
  add a second relation-value parser.
- `with=links` keeps `links` exactly as it is (raw parse, resolution status, for rendering) and

  mention rows), **Linked from** (relation, then mention, as today), and the graph. Each group
  renders only when it has rows; the section count sums both directions. The empty state appears
  only when `links_to` and `backlinks` are both empty, and is phrased for both directions.
  `GraphSection` renders whenever either direction has a row, so a record that only links out can
  open its map.
- `lib/graph.ts` builds local edges from `links_to` and `backlinks` as well as `links`; an edge is
  `{relation, mention}` flags, deduped by target. Relation rows become `relation: true`; mention
  rows become `mention: true`; a target with both keeps both flags. The centre never gets a
  self-edge. Update the graph tests with an outgoing-relation fixture.
- Keep the data honest: a missing relation target (deleted record) is still a `missing_relations`
  row on the record, not a `links_to` edge; do not invent a node.

### Checkpoint 3 — Search lands on the match

**Change:**

- A search result's `to` becomes `/s/:space/o/:object?q=<encodeURIComponent(query)>`. Recent items,
  actions, types and spaces keep their current links. A result opened from a title match still
  carries `q`; the record page decides whether there is a body occurrence.

  - actions: **Update links** (primary), **Rename only**, **Cancel**. Cancel writes nothing.
  The dialog follows the sheet geometry on a phone and the app's dialog geometry from `sm` up, with
  the close control on the handedness side.
- **Update links** performs, in order:
  1. read each source's current detail (body + `rev`) if it was not already prefetched; the preview
     dialog does this while it is open, before the rename, so the source's `links` still resolve to
     this record;
  2. `PATCH` the record title with the current `rev` (the normal update path);
  3. rewrite exactly the `[[type/oldTitle]]` occurrences that resolved to this record's id before
     the rename, using the shared parser, preserving surrounding text and every other link;
  4. `PATCH` the source body with its `rev`.
  Sources are independent. A source that changed since the preview (`409`/stale rev) is skipped and
  listed as “changed, not updated”; a failed write is listed the same way. The final toast reports
  updated and skipped counts; no rollback is attempted.
- **Rename only** runs step 1 and leaves the old links to show as unknown, exactly as `0.5.0`
  behaves. It is the escape hatch, not the default.
- The rewrite helper is pure and lives in `lib/wiki-links.ts`: `rewriteMentions(body, targetId,
  typeKey, oldTitle, newTitle, resolve)` returns the new body and the count. It parses the body
  once, replaces from the end so offsets stay valid, skips code fences and inline code by using the
  parser's existing rules, preserves the original type spelling and whitespace only where the
  parser exposes it, and writes the canonical `[[type/New Title]]` for each match. Test duplicate
  mentions, two records, a link that no longer resolves, code fences, and a different-case title.
- No automatic repair on blur or on the body save. A later reload can offer nothing, because the
  old resolution is gone; that is acceptable and stated in the dialog copy.

**Acceptance:** Rename a record that two other records mention: the dialog lists both, Update links
writes the title and two source bodies, the two sources show new revisions in history and the old
link no longer renders as unknown. Rename only leaves the same sources with unknown links. Cancel
leaves the title unchanged. Rename a record with no mentions and no dialog appears. A source edited
between preview and apply is skipped and reported, not overwritten. No format change; `FORMAT_VERSION`

## 7. Decisions taken while scoping

- **The visual refresh is v0.5.2.** The user split the visual work out of this patch after review.
  v0.5.1 ships behavior only; the record-page key echo, date grammar, type scale, record sheet,
  palette width, phone save bar and motion all move to `m5.2-visual-refresh.md`. This keeps the
  trust patch shippable and gives the redesign its own critique and QA.
- **Component tests, not Playwright.** The installed Testing Library already covers the interactive
  layer that has no tests. A persistent browser runner would add a dependency and a CI job; it is
  deferred rather than half-added.
- **`links_to` is a read projection.** The server already has both facts; adding storage or a
  second index would contradict the derived-index decision in M5.
- **The local graph and the links panel use the same rows.** A graph that draws an edge the panel
  cannot explain is a lie; the checkpoint closes that gap rather than adding a legend.
- **`?q=` is view state.** It is shareable and does not write; clearing it uses `replace` so Back
  returns to the search rather than a marked/unmarked history pair.
- **Create only with a type prefix.** Guessing a type from a bare title would silently choose a
  schema; `[[plant/New fern` is explicit, `[[New fern` stays a search.
- **Repair is client-orchestrated.** The existing conditional PATCH is enough; a new route would
  add a transaction-shaped contract the store cannot provide. The dialog is explicit, the writes
  are per-source, and a conflict is reported rather than merged.
- **No visual changes in v0.5.1.** The new controls use existing primitives; even the match marker
  and the create row are drawn with existing tokens. A visual decision made here would be redone in
  v0.5.2 and would blur the two releases.

## 8. Open questions for review

1. **Should the rename repair offer Undo?** The current plan relies on history revisions and does
   not write a second rewrite. An Undo would have to rewrite every source again and would race the
   same way; if it is wanted, it is its own checkpoint and its own conflict policy.
2. **Should the phone preview tap enter Write at the end or at the nearest paragraph?** The plan
   chooses the end because source mapping is not reliable; a nearest-paragraph map is a later
   refinement.
3. **The physical-iPhone gate** from v0.4.3 remains open. No keyboard claim in this patch is
   hardware-backed until it runs.
