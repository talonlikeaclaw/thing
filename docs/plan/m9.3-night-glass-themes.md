# M9.3 — Night Glass themes

Target: schema **8 unchanged**, workspace `0.9.2` (the last `0.9.x`, landed before M10 starts). A
web-only patch: no format key, no route, no permission, no dependency. Written 2026-11-23, after
`0.9.1`.

**Status: planned. Not started.**

## Why

The accent is already a property of the space (`accent` in `space.yml`, schema 4, six contrast-tested
presets, applied live through `space.updated`). The room around it is not. Every neutral token is a
hand-picked green literal, so a Cyan space and a Pink space still sit in the same green-black room:

| Token group | Today | Where |
|---|---|---|
| ground / lift / inset / surface / raised | `#0a0e0b` `#141c16` `#070a08` `#151a16` `#1d231e` | `@theme static`, hue ≈ 150 |
| lines | `#293029` `#3a423a` `#6a746a` | hue ≈ 145 |
| text | `#edf1e8` `#a2ab9f` `#8b948b` | hue ≈ 126–145 |
| chrome text | `#d7ded3` `#ccd4c9` | hue ≈ 134 |
| glass fills | `rgba(30,38,32,.78)` `rgba(36,44,38,.84)` | hue ≈ 153 |
| pane wash, action fallback | `rgba(10,14,11,.62)` `#343834` | hue ≈ 145 |

The comments in `globals.css` say it outright: "rather than the green glass", "never the green
surface", "a tint over a green ground". Only `--color-accent`, its ink, its on-wash and its 12% wash
move per space — everything the glass is made of stays lichen.

The result is that the one signal a person chose for their space ("this is Cyan") appears as a small
selection tint on a room that still belongs to Lichen. The glass is the loudest material in the
world; it should carry the space's light.

## Locked decisions

1. **The theme is the accent.** No new `space.yml` key, no new setting, no schema bump, no
   migration: `SpaceLayout` already writes `data-accent`, and the stylesheet already keys off it. A
   space that has never set an accent keeps Lichen and therefore today's room.
2. **Hue moves; lightness does not.** Every themed token is re-expressed as
   `oklch(<L> <C> var(--theme-hue))` with the **L values taken from today's hexes**. Luminance is
   what the contrast budget is spent on, so the budget transfers: the six themes land within 0.05 of
   Lichen's measured values on every pair (table below). Chroma is set per role, not derived from
   the accent's chroma (the accents range 0.079–0.155 in C; the room must not).
3. **The hue is curated per accent, per scheme.** A space's room takes the hue of the accent it is
   seen with, with Lichen pinned to the shipped `150°` (dark) / `95°` (light) so the default space
   does not visibly change in a patch release. The hues are spelled once, in the table below.
4. **The data ladder is a whisper; the glass carries the theme.** Dark ladder chroma stays
   `0.012–0.030` (a tinted black, never a coloured app); the glass fill rises to `0.035` at the same
   L, so a Cyan header is a teal pane and a Pink header a plum one. This is the user's read: the
   glass undertone is the theme.
5. **The neutral exceptions stay neutral.** The photo viewer and the pane wash over pictures follow
   `The Scrim Is Not a Colour Rule`: a picture is judged against grey, so nothing over a photo takes
   the space's hue. Shadows stay black (absence of light is not a hue), the lit edge stays white,
   the hover wash stays white, and the semantic pair (Ember, Amber) is fixed in every theme — an
   error text must read the same in six rooms.
6. **One selector change: `[data-accent="…"]` instead of `:root[data-accent="…"]`.** Tokens then
   apply to a subtree, which is what lets Space settings preview a room without a second copy of the
   ladder. Root behaviour is unchanged.
7. **Light mode stays a white instrument.** At `L 0.985` the sRGB gamut only allows `C ≈ 0.006` for
   the orange and pink hues, so the light glass takes a trace and the light room's variety comes
   from the bone ladder (`#f1efe6` → `#f6ecef`). The Light Is the Same Instrument Rule still holds:
   same radii, rules and type.
8. **No animated theme transition.** Custom properties do not interpolate without `@property` per
   channel; a 16-token registration to fade 200 ms of chrome is not worth the surface. The accent
   swap stays instant, as `space.updated` already delivers it.
9. **The stylesheet stays the source.** The ladder and hues live in `globals.css`; the test parses
   the file rather than duplicating it in TypeScript, because once the picker renders tokens nothing
   in TypeScript consumes the ladder.

## The ladder

`L` is today's luminance step, unchanged. `C` is new; the dark and light rows are separate so the
light room can stay nearly neutral where the gamut is narrow.

| `ground-lift` | 0.216 | 0.022 | 0.984 | 0.005 |

| `surface` | 0.211 | 0.017 | 0.984 | 0.004 |

## Shape of the change

`@theme static` keeps the token **names** and its static block; the unlayered rules below win the
cascade (the accent overrides already rely on this) and are the only definitions that ship.

```css
/* globals.css, after the @theme block */
:root {
  --theme-hue: 150;
  --color-ground: oklch(0.158 0.015 var(--theme-hue));
  --color-ground-lift: oklch(0.216 0.022 var(--theme-hue));
  --color-inset: oklch(0.140 0.012 var(--theme-hue));
  /* … the ladder's 16 rows, one oklch() each … */
  --color-glass: oklch(0.2586 0.035 var(--theme-hue) / 0.78);
  --color-glass-strong: oklch(0.2832 0.035 var(--theme-hue) / 0.84);
  --color-pane-wash: oklch(0.158 0 0 / 0.62); /* neutral in every theme */
}

[data-accent="lichen"] { --theme-hue: 150; }
[data-accent="yellow"] { --theme-hue: 98; }
[data-accent="orange"] { --theme-hue: 64; }
[data-accent="cyan"]   { --theme-hue: 206; }
[data-accent="green"]  { --theme-hue: 147; }
[data-accent="pink"]   { --theme-hue: 353; }

@media (prefers-color-scheme: light) {
  :root {
    /* the light ladder, same shape, its own L/C rows */
    --theme-hue: 95;
  }
  [data-accent="lichen"] { --theme-hue: 95; }
  [data-accent="yellow"] { --theme-hue: 96; }
  [data-accent="orange"] { --theme-hue: 52; }
  [data-accent="cyan"]   { --theme-hue: 207; }
  [data-accent="green"]  { --theme-hue: 147; }
  [data-accent="pink"]   { --theme-hue: 356; }
}
```

- The accent overrides (`--color-accent`, `-ink`, `-on-wash`, `-wash`) stay exactly as they are.
- `--color-pane-glass` stays `color-mix(in srgb, var(--color-accent) 10%, var(--color-glass))`, so
  the small glass circle over a card follows both the accent and the themed glass.
- The `@supports not (backdrop-filter)` fallbacks keep reading `surface` / `glass-strong`, which are
  now themed; the photo sheet keeps its neutral literal.
- One thing to check on the first build: whether Tailwind's compiler leaves `var(--theme-hue)` inside
  an `@theme` declaration. If it does not, the ladder lives only in the unlayered block and the
  `@theme` values stay as registration. Verified by grepping the built CSS for
  `oklch(0.158 0.015`.

## Tests

New `web/src/styles/theme.test.ts`, importing `globals.css?raw`, parsing the ladder and the hue
table, converting `oklch()` → sRGB in the test, and asserting:

- **Every accent declares both schemes' hue** and the six ids match `ACCENTS` from `lib/accent.ts`.
- **Contrast floor:** for each of the 12 theme/scheme pairs, the enumerated pairs above are ≥ 4.5.
- **Parity:** no pair scores more than 0.05 below its Lichen value — a themed room may not be less
  legible than the default one.
- **Gamut:** every parsed `oklch()` triple converts inside `[0,1]` per channel (no clipping, so the
  test's colour maths equals the browser's).
- **Allowlist:** only the ladder's roles and the two glass fills reference `--theme-hue`. A semantic,
  photo or shadow token that gains it fails, which is decision 5 enforced.
- **Wash ceiling:** the parsed `--color-accent-wash` alpha for every accent stays ≤ 0.12.

`lib/accent.test.ts` keeps its palette-table, storage and `applyAccent` cases; its three
surface-dependent cases (accent-on-ground, on-wash, ink-on-wash, glass chrome) move to the theme
test, where the surfaces are per-theme. `lib/accent.test.ts`'s hardcoded `DARK_GROUND`-family
constants are deleted rather than re-pinned.

## What changes outside the stylesheet

- **Space settings → Appearance.** `components/accent-picker.tsx`'s swatch becomes a small room
  preview: a `ground` tile holding a `glass` strip under the `accent` chip, rendered by putting
  `data-accent={accent.id}` on the tile. Because the tokens then resolve inside the tile, the
  picker's `useLightScheme` hook and its read of `scheme.accent` are deleted — the palette table
  stays for the contrast test, not for rendering. `pages/settings.tsx`'s Appearance sentence becomes
  "Sets the space's accent and the tint of its Night Glass." Six radios, roving tab stop, immediate
  write and owner-only gating are unchanged.
- **`DEFAULT_OPTION_COLOR`** in `lib/schema.ts` stays `#c8d96b`: a select option's colour is stored
  data, not chrome, and is out of scope. Named here so it is not "fixed" by accident.
- Nothing in Rust, the format, the routes or the API changes.

## Manual QA

Six accents × two schemes on the seeded space: the header and rail, a table with a selected row, the
command palette over a photo, a record sheet, the phone dock, a toast, an empty type, the no-blur
fallback, and the signed-out page (no accent: default room). The one check a machine cannot run is
the physical-device glass on iOS Safari, which stays open from `0.4.3`.

## Risks

- **Warm themes and Amber.** On `orange` and `yellow`, the fixed warning hue sits near the room's hue.
  Contrast is fine (≥ 5.56) but hue separation is weak; Amber is always paired with text or an icon,
  and the rule that no state is carried by colour alone is unchanged.
- **Lichen moves slightly.** Measured in OKLab, the default room's ground moves ΔE `0.79`
  (`#0a0e0b` → `#080f09`), its matte surfaces `0.73–0.79`, and its glass fill `1.75`
  (`#1e2620` → `#17281b`) because the fill's chroma rises by design; the accent and its washes do
  not move at all. If the glass reads wrong on the real screen, the fix is the dark glass chroma
  (one number), not a second palette.
- **Chroma is the taste knob.** If a Cyan room is too strong or a Pink one too weak, adjust that
  role's C in the ladder; the contrast gates bound the top of the range.
