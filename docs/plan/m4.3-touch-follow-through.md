# Milestone 4.3 — touch follow-through

Everything below is the v0.4.3 execution spec. Implement top-to-bottom, one checkpoint per turn,
under the delivery protocol in [`docs/ROADMAP.md`](../ROADMAP.md). Read `docs/ROADMAP.md` first,
then this file. M1 is deployed as `v0.1.0`; M2–M4.2 are landed as `0.2.0`–`0.4.2`. Nothing here
re-opens a locked decision.

v0.4.3 is the patch after the phone release. It finishes the interactions v0.4.2 opened, without
adding a route, a file kind, a server field, a format change or a dependency. Every defect it fixes
was measured on the running app at 390 × 844 against the seeded Garden space (`scripts/seed.sh`);
the numbers in §3 are the acceptance baseline.

## 1. Scope

In scope:

- **The icon picker becomes a real surface on touch.** Today it is a `Popover` anchored to a 32 px
  glyph, positioned by the layout viewport. Inside quick capture it opens *above* the capture sheet;
  with the keyboard up it is mostly behind the keyboard. On a phone it becomes a bottom sheet built
  from the existing `SheetViewport` / `SheetPopup` primitive, in front of whatever opened it. On
  touch it opens **without raising the keyboard**, so the grid gets the screen; the search field is
  one tap away and the sheet stays above the keyboard when it does. On a fine-pointer desktop the
  picker stays the anchored popover with no visual change.
- **The picker remembers and locates.** A single row of recently chosen emoji leads the grid, and
  opening the picker scrolls the current icon into view instead of starting at the top of a long
  catalogue. The custom field accepts ZWJ emoji (family, flags) that the current 8-code-unit cap
  truncates.
- **Feedback above the keyboard.** The toast stack is fixed to the layout viewport, so a
  “Record created” toast raised while the capture title has the keyboard up is entirely behind it.
  With the keyboard down on a phone it also paints over the bottom bar. Both are fixed with the
  `--kb-height` variable and the phone bar's 56 px.
- **The phone type page stops lying and stops wrapping.** Search “Cancel” currently leaves the
  query active and hides the field; the compact toolbar wraps to a second row as soon as a query
  adds Reset, leaving the search icon stranded on its own line. Cancel clears the query, and the
  toolbar becomes five controls with a single labelled “View changed” band when the view differs
  from the saved one.
- **Capture follows the page.** On Plants, pressing `C` opens quick capture as a Chore, because the
  global opener passes no type and the fallback is the first type. The route's type becomes the
  default. Changing the type in the sheet no longer throws away values already entered for shared
  properties.
- **Truthful loading and the text floor.** The type header says `0 records` while the list is still
  loading. Three routes still use 10.5 px functional text, below the 11 px floor v0.4.2 declared.
- **An audit sweep of every route**, including the ones the v0.4.2 checkpoint list missed
  (`/s/:space`, `/trash`, `/members`, `/changelog`), and the physical-iPhone keyboard gate that
  v0.4.2 left open.

Out of scope, deliberately:

- **No search milestone.** Full-text search, backlinks, wiki links and the graph stay in M5.
  Palette record search keeps its current title/body endpoint.
- **No offline, PWA, service worker, install prompt or push.** Their own milestone.
- **No server, core or format change.** `FORMAT_VERSION` stays `4`; `crates/**` is untouched.
- **No new dependency.** The recents list is `localStorage`; the picker uses Base UI `Dialog` and
  the existing sheet CSS.
- **No navigation change.** The bottom bar keeps three controls; Schedule stays in the space
  drawer, where it already carries its overdue count.
- **No desktop redesign.** The fine-pointer picker popover, the desktop toolbar and the desktop toast
  position stay as they are.
- **No performance work.** The production bundle is 1,095 kB / 325 kB gzip with no route splitting;
  that is a separate milestone, not this patch.
- **No stacked phone cards, no native gestures, no emoji catalogue expansion.** The catalogue stays
  local and curated.
- **No hiding mono option keys in select lists.** Keys are the product's signature; the v0.4.2
  record-page rule was about a *duplicate* key under its own label, which is a stronger case.

Success is: on an iPhone, tapping the icon in quick capture opens a sheet **in front of** the
capture sheet, the keyboard drops, and the search, recents and most of the grid are visible at once;
tapping the search raises the keyboard and at least four grid rows plus the custom field stay above
it; `Escape` closes only the picker; creating a record with the keyboard up shows a visible “Record
created” toast above it; on the Plants page `C` opens capture as a Plant; switching the type keeps
matching values; on a 390 px phone with a search or filter active the toolbar is one 44 px row and a
single “View changed” band, never a wrapped mess; and no functional text on any route is below 11 px
except the documented 10 px mono table key echo on a fine pointer.

Settled 2026-10-27, before checkpoint 1:

- **The touch picker is a bottom sheet below 640 px or on a coarse pointer; above 640 px with a
  fine pointer it remains the anchored popover.** A CDP `Emulation.setTouchEmulationEnabled` flips
  `(pointer: coarse)` only for the lifetime of that session, and this harness's
  `tab.emulate({ hasTouch: true })` does not persist the media feature, so a 390 px window is the
  reliable way to exercise the sheet; it is also exactly where a popover has no room. A
  coarse-pointer tablet above 640 px still gets the sheet.
- The compact toolbar is **five controls** (search, filter, sort, columns, view). The v0.4.2 rule
  “Save view and Reset in the same row, never on their own line” is replaced by an explicit
  “View changed” band; a labelled band is better than a wrap.
- Picker recents are **browser-global** (`thing:emoji:recent`, eight entries), not per user: a
  chosen glyph is a UI preference, not content, and the picker has no user id. If per-user recents
  are wanted later they can move behind the same module.
- `Escape` in a nested picker closes only the topmost dialog. Base UI already counts nested
  dialogs and passes `escapeKey: isTopmost`; checkpoint 1 verifies it rather than assuming it.

  `CHANGELOG` in `web/src/content/changelog.ts` is ordered newest first; the workspace version lives

## 4. Contracts

### 4.1 Media hooks

New `web/src/lib/media.ts`:

```ts
export const COMPACT_QUERY = "(max-width: 639px)";
export const COARSE_QUERY = "(pointer: coarse)";

/** Width-only compaction, as the type page already uses. */
export function useCompactWidth(): boolean;
/** A touch-first device: no fine pointer, e.g. a phone or a tablet. */
export function useCoarsePointer(): boolean;
```

Both are `useSyncExternalStore` over `matchMedia`, with a `false` server snapshot, exactly like the
current local hook in `type-table.tsx`; `type-table.tsx` imports `useCompactWidth` from here and
deletes its copy. `IconPicker` chooses the modal surface with
`useCompactWidth() || useCoarsePointer()`.

### 4.2 The picker on touch

`icon-picker.tsx` splits into three pieces:

- `IconPicker` — trigger + open state (unchanged markup and variants).
- `EmojiPanel` — the search field, the scrollable groups, the custom field, “Use” and “No icon”, with
  no positioning of its own. It receives `value`, `onChoose`, `autoFocus` and a `layout` of
  `"popover" | "sheet"` only for sizing.
- The two containers: the existing `Popover` for a fine pointer at `sm` and up, and a `Dialog` for
  compact or coarse pointers.

The sheet container:

```tsx
<Dialog.Root open={open} onOpenChange={handleOpenChange}>
  <Dialog.Portal>
    <Dialog.Backdrop className="fixed inset-0 z-40 bg-ground/85" />
    <SheetViewport>
      <SheetPopup
        ref={popupRef}
        className="sm:w-[24rem]"
        initialFocus={() => popupRef.current ?? true}
        finalFocus={() => returnFocusRef.current ?? false}
      >
        <Dialog.Title className="sr-only">Choose an icon</Dialog.Title>
        <EmojiPanel layout="sheet" /* search + grid + footer */ />
      </SheetPopup>
    </SheetViewport>
  </Dialog.Portal>
</Dialog.Root>
```

Requirements:

- **In front, not above.** The sheet is a sibling overlay on the same visual-viewport geometry as
  the capture sheet, so its bottom is the keyboard's top edge and its footer stays reachable. It
  must not be positioned by `floating-ui` against the trigger.
- **No keyboard on open (touch).** The sheet focuses its own popup element, not the search input, so
  opening it from the capture title dismisses the keyboard and the grid gets the full visual
  viewport. Tapping the search raises the keyboard; the sheet is already keyboard-aware and shrinks
  above it. This is the opposite of the palette rule, and deliberately so: the palette exists to
  type, the picker exists to browse.
- **Return the trigger.** Capture the trigger element in a ref before opening
  (`returnFocusRef.current = triggerRef.current`) and pass `finalFocus` that ref, **not**
  `sheetReturnFocus()`: that helper deliberately declines elements inside a sheet, and the capture
  trigger is inside one.
- **Nested dialog.** The picker's `Dialog.Root` stays inside the capture's React subtree. Base UI
  counts nested dialogs (`onNestedDialogOpen`) and only the topmost handles Escape and its own
  backdrop; checkpoint 1 verifies that Escape closes only the picker and a second Escape closes the
  capture. The picker's backdrop is its own; it never closes the parent.
- **One search row is the header.** On a phone with the keyboard up there is no height for a title
  row: the search field, a handedness-aware close control, then the grid. On `sm` and up the sheet
  may show the `Icon` title. `Dialog.Title` is always present (visually hidden when the search row
  is the only header).
- **Grid sizing.** `.sheet-popup` is already a `flex` column capped at
  `min(85dvh, var(--vv-height) - 1rem)`, so `EmojiPanel` fills it with its own `flex min-h-0
  flex-col`: the search row and the footer are `shrink-0`, the scroll area is
  `min-h-0 flex-1 overflow-y-auto overscroll-contain`, and the footer carries `.sheet-footer`. Cells
  are a 44 px minimum and the grid is `grid-cols-[repeat(auto-fill,minmax(2.75rem,1fr))]`, so a
  320 px phone gets six columns and a 390 px phone seven; the popover keeps its fixed eight. Group
  labels stay sticky at the top of the scroll area. A 320 × 568 phone with the keyboard up keeps the
  search and the footer; the grid is what gives up height.
- **No layout change to content.** Search results, empty-search copy, group order, `aria-pressed`,
  “No icon” disabled state and `aria-label`s stay exactly as today.
- **Desktop unchanged.** Above 640 px with a fine pointer the `Popover`, `sideOffset`, `w-[20rem]`
  and `max-h-64` grid are retained, including `autoFocus` on the search input.
- **Dismissal fallback, only if measured.** If checkpoint 1's two iPhone results show the capture
  title's keyboard stays up when the picker opens, blur the active element before `setOpen(true)`
  (`document.activeElement instanceof HTMLElement && document.activeElement.blur()`) and re-test.
  The picker never requests focus on the search field, so no keep-mounted focus trick is needed.

### 4.3 Picker content: recents, current, custom

New `web/src/lib/emoji-recent.ts` + `emoji-recent.test.ts`:

```ts
export const EMOJI_RECENT_KEY = "thing:emoji:recent";
export const EMOJI_RECENT_LIMIT = 8;

export function readEmojiRecent(storage: RecentStorage): string[];
/** Newest first, deduped, capped; a refused write is swallowed. */
export function recordEmojiRecent(storage: RecentStorage, char: string): string[];
```

- A stored entry is a string of 1–32 UTF-16 units; a malformed JSON array or any bad entry yields
  `[]`, mirroring `lib/recent.ts`. Tests cover malformed JSON, a wrong-shaped entry, dedupe/reorder
  and the eight-entry cap.
- The picker renders a **Recent** group first, only while the query is empty and the list is
  non-empty. Names for catalogue glyphs come from `EMOJI_GROUPS`; a custom glyph the catalogue does
  not know uses the glyph itself as its `aria-label`.
- Choosing any glyph — catalogue or custom — records it. “No icon” does not.
- When the sheet or popover opens with an empty query, scroll the `aria-pressed` cell into view
  (`block: "center"`) inside the scroll area on the next frame. Do not scroll while a query filters
  the grid.
- The custom field's `maxLength` rises from `8` to `32` so ZWJ sequences (family, flags, skin-tone
  combinations) fit; the value is still trimmed before `onChange`. Verify with `👨‍👩‍👧‍👦` (11 UTF-16
  units) through the picker into a record's frontmatter.

### 4.4 Toasts above the keyboard and the bar

`styles/globals.css`:

```css
.toast-stack {
  bottom: max(1rem, env(safe-area-inset-bottom));
}

@media (max-width: 63.99rem) {
  .toast-stack {
    bottom: calc(3.5rem + env(safe-area-inset-bottom) + 0.5rem);
  }
}

:root[data-keyboard="on"] .toast-stack {
  bottom: calc(var(--kb-height, 0px) + 0.5rem);
}
```

The keyboard rule follows the media rule so iOS wins. On Android the layout viewport is already
resized by `interactive-widget=resizes-content`, `--kb-height` stays `0`, and the phone rule keeps
the toast above the bar; on iOS the keyboard rule lifts it above the keyboard. The toast may overlap
an open sheet's footer for its short life; visibility beats silence. Desktop keeps 1 rem.

### 4.5 Phone search truth

- `SearchBox`'s compact **Cancel** calls `clear()` and then collapses. It must not clear filters or
  sorts, only the query.
- A URL with `?q=` still opens expanded; collapsing is only possible with an empty query, so a
  hidden search term cannot exist.
- The `q !== ""` effect in `type-table.tsx` stays as the URL-entry guard; no new state.
- Verify: search → Cancel → all records, no `?q=`, the search icon is inactive; reload a URL with
  `?q=fern` → the field is expanded with “fern” and the table is filtered.

### 4.6 One-row phone toolbar and the View band

- The compact toolbar renders exactly five children in every state: **search** (or the expanded
  field + Cancel), **Filter**, **Sort**, **Columns**, **View**. Each is a 44 px square. Five is not
  arbitrary: at 320 px the content width is 272 px, and even the current no-query set of seven
  44 px controls plus gaps needs 332 px, so a clean view cannot fit a 320 phone today.
- The three extra square controls leave the toolbar. Their panels stay reachable: the View sheet
  gains a **menu** state as its first screen with three 44 px rows — **View settings**, **Save as
  view…**, **Data — CSV** — and choosing one shows that existing panel in the same sheet, with a
  `Back` control in the header. `viewPanel` becomes `"menu" | "settings" | "save" | "data"` and
  defaults to `"menu"`; the desktop kebab popover keeps its three direct items. The View trigger's
  `aria-label` is `View`.
- When `dirty || hasOverrides`, render one labelled band directly under the toolbar:
  - left: a label with an accent dot — `View changed` (dirty) or `Search applied` (search only);
  - right: `Reset` (when `hasOverrides`) and `Save` (only when `dirty`, primary, 44 px).
  The band is one row at 390 px and never wraps. Saving removes it; Reset removes the query, filter
  and sorts.
- Desktop toolbar, Save/Reset behaviour and the View sheet's three panels are unchanged; only the
  phone sheet's first screen and Back control are new.
- Verify at 390 with (a) one filter, (b) one filter + one sort, (c) a search, (d) a dirty view:
  the tool row stays 44 px tall, the band is 44 ± 2 px, and no control moves to a second row.

### 4.7 Capture follows the page

- `QuickCaptureProvider` gains a `currentType?: string` prop. `AppShell` derives it from the route:
  `/s/:spaceId/t/:typeKey` uses the param; `/s/:spaceId/o/:objectId` reads the object's type from
  the existing `useObject` query (same query key as the record page, so no extra request in practice).
- `open(typeKey?)` resolves `typeKey ?? currentType` as `requestedType`. An explicit hint from the
  type page's “New record” still wins; the last-captured type remains the fallback when the route
  has no type; the first type remains the final fallback.
- The resolver's `exists` check already rejects a key that is not in this space's type list.
- `chooseType` no longer clears `values`. It keeps resetting `invalid`, the editor epoch, the error,
  the problem field and the optional disclosure. `submit` iterates the **selected** type's required
  and optional fields, so a value for a property the new type does not carry is never written; it
  survives a switch back.
- Verify: on Plants, `C` selects Plant; on a Plant record, `C` selects Plant; on the space home, `C`
  uses the last-captured type; fill a title and a required date, switch Chore ↔ Plant, switch back —
  the date is still there; the POST body contains only the selected type's keys.

### 4.8 Truthful count and the text floor

- `recordCount` renders `— records` while `objects.isPending` (all view kinds), and `N records` or
  `shown of total` after data lands. The pager already waits for `objects.data`.
- Replace every visible `text-[10.5px]` with `text-[11px]`: `pages/space.tsx` (recents meta, type key,
  type counts), `pages/trash.tsx` (revision/trashed line), `pages/members.tsx` (invite line). Keep the
  single allowed `text-[10px]` table key echo behind `showKey` (`views/table-view.tsx`).
- `DESIGN.md` says the 11 px floor applies to every route, and names the table key echo as the one
  documented exception.

## 8. Assumptions and contingencies

- **The picker's sheet path is gated on compact width as well as a coarse pointer.** The harness
  cannot make `(pointer: coarse)` true, and a 390 px window is exactly where a popover has no room;
  this keeps the path testable in headless Chromium. A coarse-pointer tablet above 640 px still gets
  the sheet.
- **Base UI nested dialogs are the mechanism, not a hope.** The library already tracks nested open
  dialogs and disables Escape on the parent; checkpoint 1 verifies Escape, backdrop and focus
  return. If the parent's focus guard pulls focus back from the picker's popup, the fix is to keep
  the picker's `Dialog.Root` in the capture popup's React subtree (it already is) and, only if
  needed, wrap the pair in Base UI's `FloatingTree`; do not convert the picker back to a popover.
- **iOS keyboard dismissal is the one experiment.** The picker focuses its own popup rather than
  the search input, which should blur the capture title and drop the keyboard. If either phone
  keeps it, the trigger blurs the active element before opening (§4.2); there is no focus-on-field
  trick to fall back to, because the picker does not want the keyboard.
- **Toasts above the keyboard may cover a sheet footer for a moment.** That is the chosen trade:
  a visible confirmation with an `Open` action over an invisible one. If the device pass shows the
  toast blocking the very button just tapped, prefer raising it above the sheet's header instead of
  hiding it.
- **Recents are a browser preference, not content.** They never sync, never join a space and never
  touch a file. A per-user key can be added later by passing the user id; it is not needed now.
- **The five-control toolbar is a deliberate revision of v0.4.2.** The old “Save/Reset in the same
  row” rule produced a 92 px wrapped bar with the search icon exiled to row 2. A labelled band is
  the fix; the plan does not preserve the old rule.
- **The 11 px floor now covers every route.** The v0.4.2 sweep skipped `/s/:space`, `/trash` and
  `/members`; that is why three 10.5 px lines survived. Checkpoint 6 runs the detector on the full
  route list so the next patch cannot repeat it.
- **Android is emulation only.** No Android hardware is available. The sheet geometry and toast
  offsets should work because Chrome resizes the layout viewport; if emulation disagrees, the plan
  follows the earlier rule and states the limit rather than claiming a device check.
- **The physical iPhone gate can stop the milestone.** If a phone is unavailable in checkpoint 1 or
  7, stop and report; do not claim a keyboard behaviour from emulation.

## 9. Other candidates, deferred

Ideas from the same audit that are real but do not earn a checkpoint in this patch. They are
recorded so the next patch starts from the same list instead of re-discovering them.

- **Schedule in the phone bar.** The agenda is the daily surface but sits behind the space drawer;
  a fourth 44 px item with the overdue count would make it one tap. Deferred because it changes the
  navigation model v0.4.2 deliberately left alone, and the drawer already carries the badge.
- **An inline add-row in the table.** A trailing empty row that creates a record on Enter would beat
  opening capture for a quick title. Deferred: it introduces a second creation path, and the
  table's New record already opens capture with the right type.
- **Search by property value in the palette.** Finding records by room or tag is a real ask once
  the palette is the front door, but it needs M5's index; the current endpoint searches title and
  body.
- **A toast/undo history.** Toasts are the only place an undo lives, then they are gone. A small
  activity list would make a lost undo findable, but there is no evidence of the loss in daily use
  yet.
- **Hiding mono keys in select and relation lists on phones.** They are noise beside the option
  name, but the key is the product's signature. Reopen only with a real complaint.
- **Route-level code splitting.** The initial bundle is 1,095 kB / 325 kB gzip in one chunk. Splitting
  the auth screens and the schema editor would help a cold phone load, but it is a performance patch
  with its own measurements, not an interaction patch.
- **Recents across devices.** Recents are browser-local today; syncing them would need a per-user
  server field for what is a UI preference, not content.
- **A draft guard on capture.** The record page guards unsaved changes; capture does not. Deferred
  because capture is deliberately disposable and a confirm on every dismiss would slow the repeated
  capture loop that the sheet exists for.
