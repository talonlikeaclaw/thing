## Fixture

A temporary server on port 8090 (`THING_DATA_DIR=/tmp/thing-qa-091`, `THING_STATIC_DIR=web/dist`)
with one fresh Garden seed run against it. The seed now demonstrates the depth half:

- `price` carries `validation: {min: 0}` beside its USD display;
- `related_plants` counts only the records its relation links whose room is `study`;
- `replacement` is a second relation to Plant whose picker offers only the study's plants, because
  `related_plant` is read by two rollups and may not be narrowed itself;
- a `Journal` type with one text property exists and the space PATCHes `daily_type: journal`, so
  Today has a note to open.

The seed's Plant membership first names the base columns, then the filtered rollup and relation are
defined: a filter is validated against the target type's members, so the target must carry the
filtered property before the definition saves. Running the seed found that ordering; the script now
does it and finishes cleanly.

The seed does not ship a member, a default or a one-to-one relation, so the QA-only fixture added
them through the ordinary API on the same temporary space: `Caretaker` (`member`), `Successor`
(`relation` to Plant, `one_to_one`), a `default: 0` on the Plant's `price` membership, and
`caretaker` among the default view's columns. Monstera was given `Caretaker: Talon` and
`Successor: Snake plant` so a second link to Snake plant can be refused.

## Method

- Widths `390 × 844`, `768 × 1000`, `1024 × 1000`, `1440 × 1000`; `prefers-color-scheme` dark and
  light.
- The 390 state is a narrow desktop viewport with a fine pointer, not a touch device. No coarse
  pointer or physical touch device was attached, and no touch claim is made.
- Overflow is `documentElement.scrollWidth - innerWidth`. A sentence is counted as clipped when its
  own `scrollWidth > clientWidth`; a footer cell is counted the same way on its inner span.
- Surfaces: the Plant ledger with the member column and the filtered total, a refused `price` cell,
  the capture sheet with the seeded default, Monstera's member chip and relations, the Fiddle-leaf
  fig one-to-one refusal, the daily note at four widths and the 0.9.1 changelog.

## Decisions taken

- **The QA-only member, default and one-to-one are API writes, not seed content.** The checkpoint's
  seed list names validation, the two filters and the daily type; the member column, the default
  and the one-to-one stay QA fixtures so the demo keeps the shape the plan specified.
- **A filter needs its target columns first.** `target_filter.room` and the rollup's `room`
  condition were refused with `is not a property of type plant` until the Plant membership carried
  Room, so the seed PATCHes the base membership before defining the filtered property and relation.
  The seed is the demo, not a migration; no other space was touched.
- **The one-to-one refusal is a record-save refusal.** The relation reads optimistically as
  `Snake plant` with `SAVE FAILED` / `Retry`, while the file stays at its previous revision; Retry
  re-attempts the same write. That matches the record sheet's save row, and no second toast is
  invented for it.
- **The 390 footer's 3 px overrun is recorded, not changed.** It is the existing compact-band
  behaviour on a date range and the full sentence is in the accessible name; the release's
  acceptance names the refusal, the member chip and the daily title, all of which fit.
- **No physical touch device was attached.** Touch behaviour is inherited from the shipped shell and
  was not re-claimed here.
