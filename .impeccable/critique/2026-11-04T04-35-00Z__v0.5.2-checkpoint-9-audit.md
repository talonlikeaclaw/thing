# v0.5.2 checkpoint 9 — technical audit

Run against the live SPA at the checkpoint-9 tree (`0.5.1` workspace, Garden space seeded),
Chromium via the browser harness, headless. Every number below was measured in the page, not
estimated.

**Coverage.** Eleven routes — `/`, the space cover, the type table, the schedule, the record,
schema, members, space settings, trash, changelog, account settings — at 1440 × 900 in both
schemes, and at 390 × 844 with a real touch emulation (`Emulation.setTouchEmulationEnabled`,
five touch points), both schemes. Plus `impeccable detect` over `web/src`.

**Method notes.**
- Contrast, target size and overflow are computed in the page: text colour composited over the
  nearest opaque ancestor ground, WCAG 2.1 relative luminance, 4.5:1 (3:1 for large), and the
  same walk for every interactive element's painted box.
- Focus indication is read after real key events (`Tab`), not `element.focus()`: programmatic
  focus does not set `:focus-visible` and produced four false positives on the first pass.
- A coarse-pointer pass is only valid when `matchMedia('(pointer: coarse)')` is asserted true in the
  same evaluate that measures. Re-applying the emulated viewport after navigation sometimes leaves
  the flag false, and a sweep that trusts it silently measures fine-pointer sizes (36–40px) and
  reports them as failures. The first sweep in this run did exactly that; every coarse number
  below is from an asserted pass.
- The emulator reports `hover` and `pointer` as `none` unless touch emulation is enabled. That
  makes every `hover:`/`group-hover:` rule inert in this environment; those surfaces were
  verified through the keyboard path and by rule inspection instead, and that limit is stated
  with each finding rather than reported as a pass.

## Held up

- **Contrast:** zero failures on all 11 routes at 1440 in both schemes, and at 390 in both
  schemes. This includes every accent-on-wash surface the checkpoint 8 token covers — the active
  schema row, `scheduled`, the table count chips, the palette's selected row, the pressed filter
  and sort chips — and the new mono key chip on the focused table header (muted on raised, 6.4:1).
- **Coarse targets:** with the pointer asserted coarse, zero controls under 44 × 44 and zero fields
  under 16 px at 390 on all 11 routes. The only sub-44 boxes left are a 1 × 1 `aria-hidden` Base UI
  mirror input and two 16 × 16 checkboxes, each inside a ≥ 44px label. The 34 × 44 inline `Purge`
  from the checkpoint-7 audit is now 44 × 44. **The space map's nodes were not covered by the first
  probe** (it skipped boxes under 24px): they measured 113 × 14 and are fixed in this checkpoint —
  see the critique.
- **Overflow:** `scrollWidth === innerWidth` on every route at 390; no horizontal document scroll.
- **Focus:** 34 sequential tab stops on the record, 97 on the table, 46 on the schedule — every
  one paints an outline except the record title input (see the P3 below).
- **Reduced motion:** the entrance animations (`.settle`, the sheet, the palette, the toast) are

- **Closed overlays:** both closed dialogs are `inert`, `hidden` and `pointer-events: none`; the
  closed command palette's listbox is `inert` and non-interactive.

## Findings

### [P1] The date field had no visible focus ring — fixed

**Location:** `web/src/components/property-field.tsx:233`.
**Category:** Accessibility. **WCAG 2.4.7.**

The visible field (`div[aria-hidden]`) and the native `<input type=date>` that takes focus are
**siblings** inside a `div.relative`, and the ring lived on the visible one as
`has-[:focus-visible]:outline-*`. `:has()` only looks at descendants, so the rule could never
match: tabbing to `Next watering` moved focus into a 1 × 1-less field with no indicator at all.
Measured: `input:focus-visible` true, `div:has(:focus-visible)` false, wrapper outline `none`.

**Fixed** by moving the ring onto the shared wrapper. Verified: the wrapper now reports
`outline: solid 2px rgb(200, 217, 107)` on keyboard focus, and the accent ring is visible around
the whole 40 px field.

### [P2] The record left a 96 px void under the save row on a phone — fixed

**Location:** `web/src/components/space-layout.tsx:130`.
**Category:** Responsive / layout rhythm.

Space pages reserved the phone bar twice: the layout carried `pb-24` and the page footer carries
`max-lg:pb-24`. With the save row now in flow, that produced 136 px of empty ground between the
save row and the footer — the row read as floating mid-screen at the end of the scroll.

**Fixed** by dropping the layout's duplicate reservation. Measured after: save row bottom 617,
footer top 657 (a standard 40 px section gap), footer still clears the phone bar.

### [P2] The shortcut sheet is not a keyboard reference

**Location:** `components/shortcut-sheet.tsx`.
**Category:** Accessibility / implementation integrity.

Three rows (`⌘K`, `?`, `Esc`) against the keys the app actually binds: capture `C`, save
`⌘/Ctrl+S`, `⌘/Ctrl+Enter`, the editor's formatting keys and the palette's arrows/Enter. The sheet
also moves focus to its Close control on open, so the accent ring lands on the dismiss button
rather than the sheet. Not a regression in this checkpoint; carried into the checkpoint 10 scope,
where the plan already schedules it.

### [P2] The space graph is unreadable at phone width

**Location:** `components/space-graph.tsx` (`COMPACT_WIDTH = 390`), `components/graph-canvas.tsx`.
**Category:** Responsive.

The compact drawing is authored in a 390-unit box and painted into 342 px, so a 12 px label
resolves to 10.5 px and labels at the frame edge still clip (`…ep the balcony`, `Water the mont…`).
The band is honest about its edges now, but not legible. Suggested command: `adapt`.

### [P3] The record title input has no focus ring

**Location:** `components/object-panel.tsx:889`.
**Category:** Accessibility.

`outline-none` on the display-face title input; keyboard focus is indicated only by the caret.
WCAG 2.4.7 accepts a text cursor inside a text field, and a ring around a display-size line would
fight the specimen-sheet composition, so this is recorded as a deliberate exception rather than
a defect.

### [P3] Dead activity annotations

**Location:** `pages/space.tsx` (`changeSummary`).
**Category:** Copy / implementation integrity.

The margin prints the bare key (`room`, `created`) where a verb belongs; already scheduled as
checkpoint 10 and left untouched here.

## Patterns

- **The `:has()`-on-a-sibling mistake is the one systemic risk found.** Both remaining uses are
  correct (the multi-select checkbox sits *inside* its label). Any future focus decoration for an
  overlaid native control must live on the wrapper.
- **The phone bar reservation is now declared once.** Two independent `pb-24`s was the second
  double-correction found in the phone shell across the milestone; the shell and the footer
  should keep one owner each.

## Recommended commands

1. **[P2] `adapt`** — the space graph at phone width: label size, edge clipping, band proportions.
2. **[P2] `clarify`** — the activity annotation's verb, the shortcut sheet's rows, the palette's
   repeated secondary.
3. **[P3] `polish`** — the residual rhythm and copy issues from the critique.

Re-run `impeccable audit` after the fixes to see the score move.
