# v0.6.0 release QA — files and images

Run on 2026-11-06 in headless Chromium against the release build (`web/dist` served by
`thing-server` from a temporary data directory, not the owner's `./data`). Every number below was
measured in the page after the app settled; screenshots were inspected for composition and are not
stored, as in the previous sheets.

**Release:** `web/package.json` and the workspace both read `0.6.0`; the space footer and
`GET /api/health` both report `0.6.0`; the changelog's top entry reads `0.6.0` and carries neither
`Unreleased` nor `upcoming`.

## Fixture

A temporary server over `/tmp/thing-qa-06` with the built SPA:

- One `Garden` space; a `Plant` type with `Room` (select), `Photo` (image) and `Guide` (file); the
  table's columns set to `title, room, photo, guide`; a `Gallery` view whose cover is `Photo`.
- Five records: four with images, one cover-only, one trashed. Two records share the PDF path.
- Four PNGs and one PDF uploaded through the browser's own `fetch` against the real upload route;
  covers and `cover_position` written through the real PATCH route.
- The space health read reported `missing_files: []` after seeding.

## Method

- Widths `390 × 844`, `768 × 900`, `1024 × 900`, `1440 × 900`; `prefers-color-scheme` dark and
  light; coarse pointer by CDP `Emulation.setTouchEmulationEnabled` with
  `matchMedia('(pointer: coarse)')` asserted in the same evaluate as the measurement.
- Surfaces: cover, table (image and file columns), gallery, record (cover hero, image and file
  fields), schedule, schema, trash, space settings; the command palette and capture sheet at every
  width and scheme; the lightbox from a gallery tile and from the record cover.
- Overflow is `documentElement.scrollWidth - innerWidth`.
- Contrast composites each text element's colour over its ancestor background stack (alpha
  composited, gradients treated as their nearest opaque colour) and applies WCAG 2.1 (4.5:1, 3:1
  for large text).
- Focus was walked with real `Tab` presses; the lightbox used realistic key intervals because its
  focus guard moves focus on the next tick.
- Reduced motion ran under `prefers-reduced-motion: reduce` and read `document.getAnimations()`
  plus computed animation and transition values.

## Coarse pointer

With touch emulation asserted (`pointer: coarse`), the record page and the gallery were swept for
controls and inputs below the floor:

| Surface | Before | After |
|---|---|---|
| Record: attached file name | 149 × 22 button | 149 × 44 |
| Gallery: tile title link | 171 × 38 | 171 × 44 |
| Record: Replace / Remove file or image | 44 | 44 |
| Record: drop target, title, room field | 44 / 44 / 44 | 44 |
| Lightbox: Close image | 44 | 44 |
| Visible inputs | 16 px minimum | 16 px minimum |

Two gaps were found and fixed in this checkpoint: the file field's name button and link had a
22 px hit area (now a 44 px row on a coarse pointer, with the name truncating inside it), and a
gallery tile's title link was 38 px (now 44). The remaining 1 × 1 `<input type="file">` elements are
`sr-only` and opened programmatically, not touch targets.

## Cover and focal point

- The record cover is a 16:9 image in the card's inner frame above the identity band; it renders in
  both schemes at 390 and 1440 and opens the lightbox.
- Reposition: clicking the hero at 25% / 75% moved both sliders (`25`, `75`); Done closed the
  editor; Save wrote `cover_position: "25% 75%"` at `rev 3`.
- Center → Done → Save removed the key entirely (`cover_position: null`, `rev 4`), as designed.
- The cover-only record's `cover_position: "20% 80%"` appears as the gallery tile's
  `object-position: 20% 80%`; a tile showing the view's image property keeps its own framing, which
  is the documented fallback rule.

The focus trap holds when keys are pressed at human intervals; the page behind does not move: from
a record scrolled to 260 px, opening the lightbox pins the document (`html` overflow hidden) and a

brings that opener into view.

## Contrast

## Reduced motion

Under `prefers-reduced-motion: reduce` over the cover, table, record, palette, capture and
lightbox: `document.getAnimations()` is empty in every state, `.settle` reports `animation: none`,
and the sheet popup's transition is `0s`. The only transition left is a colour transition on
`.settle`, which carries no motion.

## Upload and download

- The browser's file picker (input change event, not the OS dialog) selected a 56-byte text file in
  the record's file field; the field showed `fern-note.txt` and the record became dirty, then
  auto-saved. Reloading the record showed the value persisted and the file present.
- The value renders as `a[download="fern-note.txt"]`; the real browser download wrote
  `/tmp/qa06/downloads/fern-note.txt` with the exact bytes, and the API answered `200` with
  `Content-Disposition: attachment; filename="fern-note.txt"`.
- The seeded `./data` Garden space answered its health read with `missing_files: []`, as did the QA
  space.

## Limits

- No physical phone or coarse-pointer laptop. Coarse measurements use CDP touch emulation with
  `matchMedia('(pointer: coarse)')` asserted in the same evaluate.
- The OS file dialog is not opened in automation; the hidden file input's change handler is driven
  directly, which exercises the app's pick, upload and draft path but not the OS chooser.
- Headless Chromium in this container renders the emoji glyphs used by the fixture; hover-only
  styling remains inert in the emulator and was verified through keyboard and source.
